## 摘要
面向错误的学习提供了一种清晰可理解的模型改进方式：识别模型的具体弱点，训练模型修复这些弱点，并检查这些弱点是否已被修复。我们研究如何将面向错误的学习应用于终端智能体，这类智能体通过与环境中的命令 shell 交互来解决以自然语言指定的长时程任务。现有的面向错误的方法面向单轮任务设计，而现有的智能体失败分析主要用于评估和调试智能体，而非训练智能体。我们提出不当行为驱动强化学习（MiRL），它首先对策略的错误进行刻画，以发现可泛化的不当行为：即在许多环境中反复出现的错误步骤类型。随后，MiRL 使用强化学习训练该策略：在这些不当行为发生的步骤处启动 rollout，并且仅当某次 rollout 通过测试且避免该不当行为时才给予奖励。在 Qwen3.5-4B 上，八种不当行为占错误步骤的 52.1%。经过 MiRL 训练后，该策略在未见过的前缀上平均将所测量的不当行为重复频率降低 43% 至 57%。MiRL 在 Terminal-Bench Lite 上优于 TMax-4B（51.8% 对 47.4%），在 Terminal-Bench 2.1 上与之持平（21.3% 对 20.6%），而 rollout 使用量仅为其 35%。这些结果表明，面向错误的学习可应用于现实的长时程终端任务。

## Abstract
Error-targeted learning gives a legible way to improve a model: identify specific weaknesses of the model, train the model to fix these weaknesses, and check whether the weaknesses are fixed. We study how to apply error-targeted learning to terminal agents, which solve long-horizon tasks specified in natural language by interacting with a command shell. Existing error-targeted methods are designed for single-turn tasks, and existing analyses of agent failures are used to evaluate and debug agents rather than to train them. We propose Misbehavior-driven RL (MiRL), which first profiles the errors of a policy to find generalizable misbehaviors: kinds of wrong steps that recur across many environments. MiRL then trains the policy with RL, starting rollouts at the steps where these misbehaviors occur and rewarding a rollout only if it passes the tests and avoids the misbehavior. On Qwen3.5-4B, eight misbehaviors account for 52.1% of wrong steps. After training with MiRL, the policy repeats the measured misbehaviors 43% to 57% less often on average on unseen prefixes. MiRL outperforms TMax-4B on Terminal-Bench Lite (51.8% vs. 47.4%) and matches it on Terminal-Bench 2.1 (21.3% vs. 20.6%), while using 35% of its rollouts. These results show that error-targeted learning can be applied to realistic, long-horizon terminal tasks.

## 一、核心问题与研究动机

- **背景**：错误定向学习（error-targeted learning）是一种"可读性强"的模型改进范式——找出模型的具体弱点、训练其修复、再检验弱点是否真的减少。但已有方法（Khan et al. 2025；Lee et al. 2024）都面向**单轮任务**：答错一道题就生成相似题目再训练。
- **对象转移的困难**：终端智能体（terminal agent）通过命令行交互完成自然语言指定的**长时程任务**，一条轨迹数十步，失败往往只由一两步错误造成（如"没跑测试就宣称测试通过"）。这带来两个结构性障碍：
  1. **错误的任务特异性**：许多错误步骤只属于某一个环境，逐个修复无法迁移，因此必须瞄准**可泛化不当行为**（generalizable misbehaviors，即跨大量环境反复出现的错误步骤类型）；
  2. **起点错位**：从第 1 步开始 rollout，绝大部分算力花在智能体本已做对的步骤上，而且很可能永远走不到出错的那个状态。
- **现有工作的空白**：智能体失败分析（MAST、AgentErrorTaxonomy、Who&When、AgenTracer、TermiGen）只被用来**评估、诊断、调试**，没有被用来**决定训练什么**；而终端智能体的主流提升路径是**堆环境规模**（TMax 一次训练采样 14.6K 环境，8 张 H100 跑 2–3 天）。
- **两个研究问题**：(1) 如何识别终端智能体的可泛化不当行为？(2) 如何直接在这些行为发生的步骤上训练？
- **整体含义**：论文试图把"错误分析"从诊断工具升级为训练信号，为长时程智能体提供一条**数据高效、可验证**的 RL 路径。

## 二、方法论

### 2.1 核心思想
把两个已有工具接起来：**轨迹的步骤级错误分析** ＋ **从中间状态启动的 RL**。先用错误画像找出少数高频、跨环境复现的不当行为，再以这些行为发生前的轨迹前缀为起点做 RL，并且只有在"测试通过 **且** 不重犯该行为"时才给奖励。

### 2.2 预备定义
- 环境 = 自然语言指令 + 容器 + 测试套件；策略 π 每步读入前缀 h（指令、历史步骤与输出），输出"短推理 + 一条 shell 命令"。
- 轨迹结束后测试套件给出结果奖励 r_o ∈ {0,1}。
- 错误步骤 = 被 error localizer 判定为"有问题"的步骤；把同因错误归为错误类型；跨多环境复现且不局限于极少数环境的类型称为**不当行为**；其对应前缀称为**不当行为前缀**。

### 2.3 错误画像（Error Profiling）——回答"训练什么"
**(a) 错误定位（四阶段循环）**
1. 策略从当前前缀提出下一步；
2. **error localizer**（Qwen3.8-27B）判断该步是否"虽能跑但显著提高失败概率"，若是则标记并写一句理由；
3. 对被标记的步骤，**teacher**（同族 Qwen3.8-27B，以保证纠正贴近策略自身分布）从同一前缀写出纠正步骤，纠正步骤同样要过检查；
4. 执行被接受的步骤（策略自身或 teacher 纠正），回到第 1 步。
   - 若 teacher 三次尝试内给不出通过检查的纠正，丢弃该 rollout。每步的错误步骤连同前缀与解释被记录。

**(b) 错误分类体系构建**
- **annotator**（Claude Opus 5）分批阅读错误步骤及其解释，提出带"名称 + 定义"的错误类型；跨批次反复出现的类型被保留，形成固定类型集；
- 再对全部错误步骤打标签（可多标签，也可"未分配"并注明 one_off / new_pattern / unclear）；
- 保留覆盖 ≥1% 错误步骤的类型，其余归为**长尾**。作者强调好类型要过两关：**可迁移性**（学会一半能否带到另一半）与**频率**（够不够常见）。

**(c) 实测结果**：2,017 个环境上得到 12,746 个错误步骤，8 类不当行为覆盖 **52.1%** 的错误步骤、出现在 **75.4%** 的环境中，可视为可泛化不当行为。

### 2.4 从不当行为前缀启动 rollout —— 回答"在哪训练"
- 标准 RL（GRPO / DPPO）从第 0 步重新开始，是 on-policy 的；但长时程轨迹高度随机，要"自然复现"某个特定错误代价极高。
- MiRL 改为：为每类不当行为固定抽取若干前缀，每组 rollout 从该前缀处继续。
- **关键工程难点**：记录数据只存前缀不存容器快照。解决方案是在**全新容器**中逐步重跑前缀命令，**仅当每条命令的输出与记录完全一致**才保留该前缀；对时间、随机性、网络导致输出漂移的 flaky 环境一律丢弃。保留下来的前缀所属环境即训练环境。
