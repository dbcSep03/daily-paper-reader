## 摘要
扩展面向工作型智能体的监督训练需要多样化的专业任务，以产生可靠的专家演示。然而，任务信息缺失或不一致会阻碍教师执行，并削弱所得的监督信号。我们提出 WorkFactory，一个用于构建连贯且可执行的专业任务的可扩展框架。从专业意图出发，信息级规划构建信息支撑图来指导任务实例化，显式表示预期输出所需信息的依赖关系与位置。随后，探测执行识别支撑失败并指导修复，同时保持预期工作不变。我们构建了跨越 612 种职业的 112,686 个任务，并使用收集到的教师轨迹对 4B、27B 和 35B-A3B 规模的 Qwen 模型进行微调，得到 WorkPilot 系列。所有三个模型在四个专业工作基准上均优于各自的基础模型，其中 WorkPilot-35B-A3B 在 GDPval-AA v2.1 上从 879 Elo 提升到 1565 Elo。扩展分析揭示了依赖模型的收益递减，执行长度先增加后减少。受控组件分析表明，规划与修复减少了探测诊断出的任务环境缺陷，并提升了下游性能。数据与模型可在 https://github.com/IQuestLab/WorkFactory 获取。

## Abstract
Scaling supervised training for working agents requires diverse professional tasks that yield reliable expert demonstrations. However, missing or inconsistent task information can obstruct teacher execution and weaken the resulting supervision. We propose WorkFactory, a scalable framework for constructing coherent and executable professional tasks. Starting from professional intents, information-level planning builds an information support graph to guide task instantiation, explicitly representing the dependencies and locations of information required for the intended outputs. Probe executions then identify support failures and guide repairs while preserving the intended work. We construct 112,686 tasks spanning 612 occupations and use the collected teacher trajectories to fine-tune Qwen models at 4B, 27B, and 35B-A3B scales, yielding the WorkPilot family. All three models improve over their respective base models across four professional-work benchmarks, with WorkPilot-35B-A3B improving from 879 to 1565 Elo on GDPval-AA v2.1. Scaling analyses reveal model-dependent diminishing returns, with execution length first increasing and then decreasing. Controlled component analyses show that planning and repair reduce probe-diagnosed task environment defects and improve downstream performance. The data and models are available at https://github.com/IQuestLab/WorkFactory.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：工作型智能体（working agents）需在数字环境中执行专业工作流、协调工具并产出交付物。当前主流的后训练方式是**对专家演示做监督微调（SFT）**，而将其规模化依赖大量"可执行的专业任务"。
- **核心痛点**：任务信息缺失或不一致会直接阻碍教师（teacher）执行，使轨迹无法可靠展示目标职业能力，从而**削弱监督信号质量**。
- **关键难点——信息支撑边界**：要产出有效演示，教师必须能获得**充分且一致**的信息前提；但中间计算与最终结论又必须**留给求解者自行推导**。若前提缺失，教师会引入无依据假设；若把结果直接给出，则删除了本应训练的核心工作。
- **整体含义**：论文主张"任务环境质量"而非"任务数量"是规模化专家监督的瓶颈，并提出一套从**专业意图 → 可执行环境 → 干净教师轨迹**的自动化构建框架 WorkFactory。

## 2. 方法论

### 2.1 核心思想
从**预期输出反向规划**，用**信息支撑图**显式刻画"每个输出依赖什么信息、信息应在何处提供"，再通过**探针执行**发现支撑失败并**受约束地修复**，最终交由**独立教师**采集轨迹。

### 2.2 关键技术细节

- **多源专业意图合成（§3.2）**
  - 三条路线：① 职业层级（SOC）展开为具体角色与情境；② 文档化技能组合成多步工作流（一个技能输出作为另一个输入）；③ 真实专业交付物经**指令反译**推断合理目标。
  - LLM 评审候选意图的连贯性、可行性、职业恰当性与真实性，通过后进入意图库 𝓛。

- **信息支撑图引导的环境构建（§3.3）**
  - 图定义：`G_info = (V_info, V_carrier, E_info, E_loc)`
    - `V_info`：信息单元（事实/证据、规则/定义、中间值、交付物、需求），并标注供给状态（已提供 / 外部获取 / 求解者推导 / 构建内部）。
    - `V_carrier`：载体（用户请求、参考文件、外部资源、未来交付物、内部构建需求）。
    - `E_info`：关联、变换、证据、约束等支撑关系（支持多源联合支撑）。
    - `E_loc`：信息到载体的位置绑定，并区分求解者可见 vs. 构建内部隐藏。
  - **物化**为工件级构建计划 `P = (u, A, D)`：具体用户请求 u、工件规格 A、无环构建依赖 D；worker 复用/改写/合成工件。
  - **构建检查**：程序化检查文件数量与类型；LLM 评审内容覆盖与请求一致性；失败最多重试 3 次，仍失败则丢弃。

- **基于执行的环境修复（§3.4）**
  - **探针求解器**仅见求解者可见输入（无图、无计划、无历史输出），将问题定位到被检查的源与工具观察，区分环境缺陷 / 求解者失误 / 合法开放选择；**仅 blocker 级问题触发修复**。
  - **修复器**编辑请求与现有参考文件，**保持文件数量、类型与依赖结构不变**；每轮修复须通过构建检查 + **LLM 工作保留审查**（核心目标、关键操作、实质交付要求不变）。
  - 修复后在新沙箱**重新探针**；最多 3 轮，仍有 blocker 则丢弃。

- **教师轨迹与训练（§3.5）**
  - 教师 GLM-5.3 在与探针相同的**信息访问边界**下独立执行（94,077 任务用 Stirrup，18,609 用 Claude Code）。
  - 轻量过滤（重复推理、重复工具调用、无交付物、内容过少）；对**最长 5% 的 rollout** 额外做**成对交付物比较的拒绝采样**（最多 4 次尝试，首次胜出即停）。
  - **掩码自回归监督**：
    `J_SFT(θ) = − (1/Σ|M_s|) Σ_s Σ_{ℓ∈M_s} log π_θ(a_{s,ℓ} | H_{s,<ℓ})`
    其中 `M_s` 为受监督的 assistant token 位置；**失败工具调用的 token span 从 M_s 移除**，但失败调用与其结果保留在历史中，以保留恢复行为的执行上下文。
  - 超长序列（>262,144 token）在打包前移除。

## 6. 主要结论与发现

- **训练有效性**：三个 WorkPilot 模型在 4 个基准上全面超越各自基座：
  - WorkPilot-35B-A3B：GDPval-AA **879 → 1565**；JobBench 28.91 → 62.35；Workspace-Bench 47.12 → 56.53；OmegaUse 7.14 → 21.18。
  - WorkPilot-27B：GDPval-AA 本地估计 **1612 Elo**，接近前沿模型区间。
  - WorkPilot-4B：GDPval 与 OmegaUse 上超过 Apodex-1.1-mini。
- **规模收益递减且依赖模型**：35B-A3B 前 5K 任务贡献 447 Elo，75K→110K 仅 +13；到 30K 时 35B-A3B 与 27B 分别取得 88% 与 94% 的总增益。
- **执行长度先增后减**：35B-A3B 平均轮次 24.87 → 162.88（2K）→ 85.90（110K），触顶 250 轮比例从 21.9% 降至 2.7%；工具失败率（代码执行 16.0%→6.3%，网页搜索 22.4%→10.4%）下降，网页抓取失败率稳定在 40%–48%。
- **组件互补**：信息级规划使 8 类

- **组件互补（续）**：信息级规划使 8 类缺陷中的多数显著下降——其中"关键前提未提供""请求与文件相互矛盾""信息不可获取""隐含未声明假设"四类降幅最大，而"任务本身开放度过高""交付物规格模糊"两类改善有限；在此基础上叠加**执行修复**，可进一步清除探针才能暴露的残留 blocker（尤其是跨文件一致性与外部资源可达性问题），说明"规划阶段的结构化"与"执行阶段的可验证性"针对的是不同缺陷来源，二者互补而非替代。下游 Elo 呈单调提升：直接工件级规划 < 信息级规划 < 信息级规划 + 执行修复，且增益在难任务上更明显。
- **教师能力是独立瓶颈**：在 30K 同一子集上，GLM-5.3 产出的轨迹在长度、工具调用充分性与交付物完整性上均优于 DeepSeek-V4-Flash-0731，对应学生模型的下游表现也更高，说明**环境质量提升后，教师轨迹质量仍是限制监督信号上限的第二个乘性因子**。
- **成本–性能更优**：在同等每任务推理成本区间内，WorkPilot 系列（尤其 4B 与 35B-A3B）的 GDPval-AA Elo 高于同价位对比模型；27B 以显著低于前沿模型的单任务成本进入其性能区间，体现出"数据质量换模型规模"的性价比特征。
- **行为层面的可解释变化**：随数据规模增长，模型从"过早交付/浅层尝试"转向"长程多轮执行 + 失败后恢复"，具体表现为触顶轮次比例与工具失败率同步下降；但**网页抓取失败率长期稳定在 40%–48%**，提示该类失败更多源于外部环境而非模型能力，属于环境侧而非监督侧的残余噪声。
- **污染与稳健性检查**：论文报告了去污染检查与跨基准交互长度分析，用以排除基准泄漏与"仅靠更长交互刷分"的替代解释。

## 8. 启示与可复用要点

- **方法论层面**：把"任务构建"从"写提示词"升级为**可验证的信息工程设计**——用信息支撑图显式区分"必须提供 / 应自行推导 / 应外部获取"，是控制监督信号纯度的一般性手段，可迁移到任意 agentic SFT 数据生产。
- **质量闸门设计**：**独立探针（信息边界与求解者一致）+ 受约束修复（保持文件结构与工作意图不变）+ 工作保留审查**，构成一套低成本、可自动化的"环境单测"，其思想可复用于工具调用、代码修复、多文件编辑等场景的数据校验。
- **训练细节的可借鉴点**：仅对 assistant token 计算损失、**将失败工具调用的 token span 从损失中掩码但保留在上下文中**，是一种在"不奖励错误动作"与"保留恢复上下文"之间取得平衡的实用做法。
- **规模化策略**：数据规模收益呈明显递减且依赖学生容量，实践上应优先在中小规模上做质量迭代，再按学生规模决定扩量节点（论文显示 30K 已可获得大部分增益）。
- **评估建议**：报告本地 Elo 时应同时给出估计器误差与置信区间，并辅以行为指标（轮次分布、工具失败率、触顶比例），以避免单一分数掩盖能力结构差异。
