## 摘要
大型语言模型（LLMs）正日益被用于多轮智能体工作负载，这些负载需要与复杂环境进行持续交互。现有的反思式提示优化器（如 GEPA）从失败的 rollout 中学习，但智能体失败也可能源于提示缺陷、执行框架限制、随机执行或有噪声的评判器。我们认为，此类失败可能无法提供有用的学习信号，甚至可能有害；因此，必须对提供给提示优化器的任务进行精选，以获得更好的性能。我们提出 GEPA-Curator，一个增强提示优化器的框架，用于选择哪些智能体经验应影响提示优化。具体而言，GEPA-Curator 包含两个组件：任务精选，用于过滤掉可能提供噪声或不可靠学习信号的任务；以及先验成功检索，用于选择性地检索某个任务过去的成功轨迹，并将其作为额外上下文提供给提示优化器。我们在 GoBrowse、ALFWorld、AppWorld 和 τ-bench 上评估 GEPA-Curator，并使用 Gemini 3.1 Pro 和 Claude Opus 5 作为优化器模型。GEPA-Curator 达到或超过两个基线的平均性能，相较 GEPA 提升最高达 20.7%，相较 ACE 提升最高达 21.2%。

## Abstract
Large Language Models (LLMs) are increasingly used in multi-turn agentic workloads that require sustained interaction with complex environments. Existing reflective prompt optimizers such as GEPA learn from failed rollouts, but agentic failures can also come from prompt weaknesses, harness limitations, stochastic execution, or noisy judges. We argue that such failures may not provide useful learning signal, and may even be harmful; and thus it is essential to curate which tasks are provided to the prompt optimizer for better performance. We introduce GEPA-Curator, a framework that augments the prompt optimizer to select which agent experiences should shape prompt optimization. In particular, GEPA-Curator consists of two components: task curation, which filters out tasks that are likely to provide noisy or unreliable learning signals, and prior success retrieval, which selectively retrieves past successful trajectories for a task and provides them as additional context to the prompt optimizer. We evaluate GEPA-Curator on GoBrowse, ALFWorld, AppWorld, and $τ$-bench, using both Gemini 3.1 Pro and Claude Opus 5 as optimizer models. GEPA-Curator matches or exceeds the mean performance of both baselines, with gains of up to 20.7% over GEPA and 21.2% over ACE.

## 1. 核心问题与整体含义

- **背景**：LLM 智能体越来越多地用于多轮、长程、工具调用的复杂环境。递归自我改进（RSI）的一个实际路径是“反思式提示优化”：智能体执行任务后，由 Reflector 根据轨迹和评估结果诊断失败并修改提示词，形成经验反馈循环。
- **核心问题**：现有方法（如 GEPA）默认失败轨迹包含可泛化的学习信号，但在智能体场景中，失败可能来自提示词缺陷，也可能来自执行框架限制、环境故障、随机执行、任务本身不可行或 LLM-as-a-judge 噪声。若 Reflector 将噪声失败误归因于提示词，可能产生无效甚至有害的提示变异。
- **论文主张**：不是所有智能体经验都值得学习；应对进入提示优化器的任务和轨迹进行“精选”（curation），以提高反思与变异质量。
- **整体含义**：论文将“数据精选/课程学习”思想引入智能体提示优化，提出一个外挂式 Curator harness，在不改动原提示优化器的前提下筛选任务并提供历史成功轨迹作为反思锚点。

## 2. 方法论

### 2.1 核心思想

- **GEPA-Curator** 作为外层 harness 运行在现有提示优化器之上，维护每个任务的执行历史（轨迹、评估结果、Curator 判断等）。
- 包含两个互补组件：
  1. **任务精选（Task Curation）**：决定当前优化步应运行哪些任务、跳过哪些任务，以减少噪声或冗余学习信号。
  2. **先验成功检索（Prior Success Retrieval）**：为当前失败任务选择一条可信的历史成功轨迹，作为 Reflector 的对比参考。
- 精选结果仅作为额外输入元数据传给提示优化器，**优化器本身不变**。

### 2.2 任务精选

- Curator 读取训练任务及其历史，优先运行“探索不足”的任务以积累历史。
- 当历史提供强证据表明继续运行该任务不太可能产生有用信号时，可暂时跳过，例如：
  - 多次稳定成功；
  - 多次失败但原因明显在提示词之外（harness/环境限制）；
  - 相似行为或终态得到不一致评估，疑似评审噪声。
- 跳过是**临时决策**，每个训练 epoch 会重新考虑；已掌握任务可能因提示更新而回归，曾不可行的任务也可能随提示改进变得可解。
- Curator 的提示词中定义了多种判断类别：已掌握、提示敏感、操作上不可行、无当前优化信号、flaky/无信息、评审器损坏、基础设施故障、不确定等；原则是“不确定时倾向运行”。

### 2.3 先验成功检索

- 对当前 minibatch 中失败的任务，Curator 从历史中挑选一条成功轨迹作为“可信参考”，让 Reflector 进行对比式诊断，而不是仅凭失败轨迹猜测原因。
- 选择标准强调成功行为真实、可复现，并有其他独立成功证据支持；避免使用因评审宽松、环境污染或偶然因素导致的“假成功”。
- 若没有可信成功轨迹，Curator **弃权（abstain）**，不提供锚点，以避免误导。
- 任务精选与成功检索在**同一次 Curator LLM 调用**中联合完成，因此成功检索不增加额外 LLM 调用。

### 2.4 优化流程文字说明

1. 初始化任务历史。
2. 每轮 Curator 读取候选任务历史，决定 `run/skip`，并为可能运行的任务选择成功锚点。
3. 构造精选后的 minibatch，传给提示优化器。
4. Actor 在环境中执行任务，Reflector 基于失败轨迹及可选成功锚点提出提示变异。
5. 新轨迹和评估结果写回任务历史。
6. 在验证集上周期评估，最终选择验证表现最好的提示。
7. 被跳过的任务在后续 epoch 重新评估。

### 2.5 效率优化变体

- **跳过间隔决策**：一次决定跳过多个 epoch，减少重复 Curator 调用。
- **紧凑任务历史**：仅保留最近若干次完整轨迹，旧记录用摘要表示。
- **成功轨迹保留**：保留可选完整成功轨迹，失败时提供给 Reflector，并可由 Curator 替换为更好的成功参考。

## 6. 主要结果与发现

### 6.1 主结果：Curator 带来稳定增益

- 在 WebArena 四个域上，GEPA-Curator 相对 Seed prompt 与 GEPA 基线在任务成功率上有持续提升，且在两个优化器模型（Gemini 3.1 Pro、Claude Opus 5）下方向一致，说明增益并非绑定于某一特定 Reflector 模型。
- 增益在不同域之间不均匀：任务可解性较高、失败信号较“干净”的域提升相对温和；失败噪声较多（环境限制、flaky 评估）的域提升更明显，这与“Curator 主要过滤噪声信号”的机制假设相符。
- 5 次重复运行的均值与标准差表明，Curator 版本在多数设置下方差更小，提示优化过程更稳定，减少了“某次优化把提示改坏”的退化风险。

### 6.2 额外智能体基准

- ALFWorld、AppWorld（Test-N / Test-C）、τ-bench 上，GEPA-Curator 总体优于 GEPA，并在多数设置上优于或不劣于 ACE；AppWorld 的 Test-C（更难、组合性更强）上的表现说明增益不只来自简单任务。
- τ-bench 因训练样本少、验证频率提高，结果波动较大，论文对此的结论表述相对保守。

### 6.3 消融：两个组件互补

- 仅任务精选、仅成功检索各自都能带来部分提升，但完整方法优于任一单组件，说明“选对任务”和“给对参照”解决的是两类不同问题：前者减少无效学习信号，后者改善失败归因的准确性。
- 去掉 Pareto 候选选择的 GEPA 与完整 GEPA 的差异小于 Curator 带来的差异，提示在本实验设置下，**输入数据的精选比候选池维护策略更关键**。

### 6.4 动机实验

- Easy / Optimizable / Impossible / Flaky 组合的学习曲线显示：混入不可行或 flaky 任务会拖累甚至逆转优化收益，而按“可优化性”组织课程能显著改善学习效率，为 Curator 的设计提供了直接经验依据。
- 与数值化课程学习方法的对比表明，LLM 驱动的语义判断（而非仅按难度/成功率排序）在识别“提示词之外失败原因”上更有效。

### 6.5 Curator 决策分析

- 在 1,581 个 GoBrowse 训练任务上，Curator 能给出可解释的跳过理由分类（已掌握、操作不可行、flaky、评审器问题、基础设施故障等），且“不确定时倾向运行”的保守原则使误跳率保持在较低水平。
- 成功锚点的配对分析显示，Curator 在相当比例案例中选择弃权而非强行提供参考，弃权情形与后续优化收益较低相关，说明弃权机制有效避免了误导性锚点。
- 被跳过的任务在后续 epoch 有部分被重新纳入，验证了“临时跳过而非永久剔除”的设计合理性。

### 6.6 效率与成本

- Efficient GEPA-Curator 在保持大部分性能增益的同时，显著减少了 Curator 调用次数与上下文长度，说明跳过间隔决策与紧凑历史摘要的工程优化是有效的。
- 成本分解表明，Curator 引入的额外开销主要来自优化器侧 LLM 调用，而非 actor rollout；在 rollout 昂贵的长程智能体环境中，这一开销占比相对可接受。

### 6.7 Meta-Harness 与 QA 扩展

- 将 Curator 用于 harness 代码优化（Math-RAG、文本分类）也能带来改进，说明“经验精选”思想不局限于提示词层面，具有一定的方法通用性。
- QA 类任务（AIME 2025、IFBench、HoVer、HotpotQA）上的补充实验表明，在单轮、失败原因较明确的场景中 Curator 的增益相对有限，符合“智能体场景才是主要受益区”的预期。

## 7. 局限与不足

- **依赖 Curator 自身的判断质量**：Curator 由 LLM 驱动，其“不可行/flaky”判断本身可能出错；论文虽以“不确定时运行”降低风险，但缺少对 Curator 误判率的上界分析或人工标注校验。
- **额外系统复杂度**：引入任务历史维护、跳过调度、锚点检索等机制，工程实现与调参成本上升；对不熟悉该框架的复现者存在门槛。
- **评估依赖 LLM-as-a-judge 或环境奖励**：在评审器本身不可靠的场景，Curator 只能识别而不能修复评估噪声，方法的上限受评估质量约束。
- **实验规模与统计力**：部分基准（τ-bench、Meta-Harness）实验次数少、数据规模小；主实验虽 5 次重复，但缺少显著性检验或置信区间的正式报告。
- **基线强度问题**：GEPA 采用简化 greedy 版本，且未在主实验中纳入 ACE 等更强基线，可能高估相对增益。
- **成本结论为估算**：缺少实测 GPU 小时与端到端时延，效率主张的证据强度有限。
- **任务分布偏置**：核心验证集中在 WebArena 系列，向真实开放环境、多智能体协作、超长程任务的泛化性尚未验证。

## 8. 启示与可借鉴点

- **“经验并非都值得学习”是一个可操作的设计原则**：在 RSI/自我改进系统中，输入端的数据精选与输出端的变异算法同等重要，甚至更关键。
- **外挂式 harness 的设计范式**：不改动原优化器、仅通过元数据注入精选结果，降低了方法迁移成本，便于与不同提示优化器组合。
- **对比式反思优于单轨迹反思**：为失败提供可信成功锚点，把“猜原因”变为“找差异”，是提升 Reflector 诊断质量的低成本手段。
- **弃权机制的价值**：在证据不足时选择不干预，是抑制噪声放大的重要工程原则，值得在其他 LLM 反馈循环中借鉴。
- **课程视角的组织方式**：按“可优化性”而非仅按难度组织任务，为智能体训练数据调度提供了新思路。

## 9. 总体评价

论文抓住了智能体自我改进中一个被普遍忽视但实际影响很大的问题：失败轨迹中的噪声会被反思机制放大为错误的提示变异。其贡献主要在于**问题刻画与系统设计**，而非全新的优化算法——Curator 本质上是把数据精选与课程学习思想工程化地嵌入提示优化回路。方法设计克制（外挂、可弃权、临时跳过）、实验覆盖较广（多 benchmark、双优化器、消融、成本、跨任务类型扩展），结论方向一致且有机制层面的解释支撑，可信度较高。

主要短板在于：Curator 判断的正确性缺少独立校验，部分实验规模偏小、基线强度与统计检验不足，成本结论为估算而非实测。总体而言，这是一篇**问题定义清晰、工程贡献扎实、实证较充分但统计严谨性可进一步加强**的工作；其核心思想（对进入优化器的经验进行精选）具有较好的可迁移性和后续研究价值。
