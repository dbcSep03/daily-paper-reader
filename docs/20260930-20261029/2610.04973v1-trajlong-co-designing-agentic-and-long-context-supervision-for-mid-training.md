## 摘要
用于编程、搜索和工作场所任务的LLM智能体日益依赖长上下文能力，以便有效聚合并推理扩展的交互历史。近期工作已将智能体轨迹纳入中期训练阶段，利用其天然较长且交互丰富的结构。然而，如何组织这些轨迹内部的信息以形成有效的中期训练监督仍缺乏充分探索。在本工作中，我们研究长上下文与智能体原子能力之间的关系，并提出TrajLong，一种新颖框架，将轨迹编译为具有密集监督的长上下文训练任务，面向三种代表性原子能力：证据锚定、跨证据聚合和时间状态维护。我们使用TrajLong编译的数据对Qwen3-14B-Base和Qwen3-30B-A3B-Base进行中期训练，随后进行监督微调。在6个长上下文和12个智能体基准上的实验显示出广泛的性能提升，受控消融表明其优于原始轨迹和掩码轨迹基线。能力层面的分析进一步揭示了长上下文与智能体原子能力之间依赖于任务的关联。这些发现表明，长上下文推理与智能体执行的共享能力需求为设计中期训练数据以发展下游智能体能力提供了原则性基础。

## Abstract
LLM agents for coding, search, and workplace tasks increasingly rely on long-context capabilities to effectively aggregate and reason over extended interaction histories. Recent work has incorporated agent trajectories into mid-training stage, drawing on their naturally long and interaction-rich structure. Yet how to organize the information within these trajectories into effective mid-training supervision remains underexplored. In this work, we investigate the relationship between long-context and agent atomic capabilities and introduce TrajLong, a novel framework that compiles trajectories into long-context training tasks with dense supervision, targeting three representative atomic capabilities: evidence grounding, cross-evidence aggregation, and temporal state maintenance. We mid-train Qwen3-14B-Base and Qwen3-30B-A3B-Base with data compiled by TrajLong, followed by supervised fine-tuning. Experiments on 6 long-context and 12 agent benchmarks demonstrate broad performance gains, with controlled ablations showing improvements over raw and masked trajectory baselines. Capability-level analyses further reveal task-dependent associations between long-context and agent atomic capabilities. These findings suggest that the shared capability demands of long-context reasoning and agent execution provide a principled basis for designing mid-training data to develop downstream agent capabilities.

## 1. 核心问题与整体含义

- **研究背景**：面向编程、搜索、办公等任务的 LLM 智能体需要长上下文能力，以聚合和推理跨多轮交互的历史信息。智能体轨迹天然具有长且交互丰富的结构，近期工作已将其引入中期训练（mid-training），让基座模型在后续适配前接触工具使用模式和证据引导的导航行为。
- **核心问题**：如何把轨迹中异构、冗长的信息组织成**有效的中期训练监督**，而非简单地对完整轨迹做下一词预测。
- **现有做法的不足**：
  - 全轨迹下一词预测会对工具观察等非助手内容计算损失，把噪声引入训练目标；
  - 损失掩码虽将监督集中在助手推理与动作上，但被掩码内容仍需作为上下文处理，训练 token 效率降低；
  - ACC 等方法虽将轨迹证据编译为长上下文 QA，但未系统针对不同长上下文原子能力进行组织。
- **整体含义**：论文试图论证长上下文推理与智能体执行共享能力基元，并据此设计中期训练数据，为下游智能体能力发展提供原则性依据。

## 2. 方法论

### 2.1 核心思想

TrajLong 将智能体轨迹**编译**为面向三种长上下文原子能力的训练任务，并在编译后的上下文、问题与目标回答上施加**全 token 稠密监督**：

- **证据锚定（Retrieval）**：从长上下文中精确定位特定证据项；
- **跨证据聚合（MultidocQA）**：跨多来源、多轮次进行多跳推理与聚合；
- **时序状态维护（State Tracking）**：追踪同一对象在多次更新下的演化状态。

### 2.2 问题形式化

- 轨迹记为 \(\tau=(z_1,\dots,z_N)\)，训练记录 token 序列为 \(x=(x_1,\dots,x_L)\)，监督掩码 \(m_t\in\{0,1\}\)。
- 损失函数：
  \[
  \mathcal{L}(\theta;x,m)=-\frac{1}{\sum_t m_t}\sum_{t=1}^{L}m_t\log p_\theta(x_t\mid x_{<t})
  \]
- 与原始轨迹全监督、掩码监督不同，TrajLong 保留下一词预测目标，但**重组轨迹信息**为能力定向训练样本，并在固定 token 预算下对上下文与所有问答对全量监督。

### 2.3 轨迹预处理

- **来源**：真实软件开发与办公场景的智能体轨迹，统一为交互格式。
- **隐私保护**：
  - 用户级去标识：替换个人标识、认证材料、环境特定标识，同类重复值保持一致替换；
  - 组织级排除：含明显公司标识或内部文档的整条轨迹丢弃；
  - 任务级语义筛查：LLM 判断任务是否涉及敏感个人信息或机密项目，命中则整条丢弃。
- **任务安全**：LLM 评估恶意网络攻击、钓鱼、欺诈、危险武器指令等有害意图，不安全轨迹整条排除。
- **清洗过滤**：规则+LLM 检查格式有效性、任务完整性、交互质量；剔除重复循环、高错误率、低价值动作，保留错误恢复与渐进探索等高价值模式；去除 agent harness 格式噪声，澄清用户指令，精化工具响应格式。
- **领域分类**：按任务意图与工具使用模式分为**代码**与**搜索**两类。

### 2.4 能力定向编译（三种编译器）

给定预处理轨迹 \(\tau\)，证据项集合 \(E(\tau)=\{o_i\}\)，能力编译器 \(C_k(\tau)=\{(c_j,q_j,y_j)\}_j,\ k\in\{\text{Ret.},\text{QA},\text{ST}\}\)，其中 \(c_j\) 为构造上下文，\(q_j\) 为新问题，\(y_j\) 为教师模型生成的目标回答，参考答案 \(a_j\) 用于构造或校验最终答案。

- **证据锚定（Retrieval）**：
  - 利用单次搜索返回的多个同主题但内容不同的段落作为“天然针”与干扰项；文件交互则指定路径、读写操作与出现次序。
  - 问题同时指定主题与组内位置，仅靠主题匹配不足以定位；70% 搜索问题额外要求随机 10 字符字母数字前缀，30% 仅要求原文复现。
  - 参考答案从**渲染后的上下文**中恢复，确保格式清洗与去标识不造成答案-上下文错位；校验目标唯一性、答案-上下文对齐、最终答案保真度。
- **跨证据聚合（MultidocQA）**：
  - 按任务连续性将交互轮次分组，提取文件、文档、执行证据，保留来源与版本标识；同一文件不同内容共享来源身份并推进版本号。
  - 上下文按来源分组、组内版本排序、来源组随机置换，每块显示证据 ID、标题、版本标签。
  - 三阶段构造：多样化问题生成（9 类问题×9 类答案，兼容配对）→ 最多两轮多跳依赖增强（补充证据、构建多跳链或互补约束）→ 最终精化与检查（剪枝冗余支持项、审查可答性/歧义/干扰项有效性）。
  - 教师模型在完整证据集合上独立求解，校验最终答案一致性与解答一致性。
- **时序状态维护（State Tracking）**：
  - 对齐工具调用与响应，按文件组织时间线；仅显式成功操作贡献状态更新。
  - 从完整 Write 载荷或可判定完整性的 Read 作为锚点 \(s_0\)，重放成功编辑 \(s_t=U(s_{t-1},e_t)\)，保留未触碰内容；后续完整 Read 用于校验。
  - **Snapshot 问题**：请求某次成功 Edit 前/后、最终状态、或回滚连续后缀编辑后的完整文件；上下文在目标文件首次后续成功 Read 前截断，防止直接复制。
  - **Provenance 问题**：识别某片段最后写入、首次出现、被移除的操作类型与文件内成功操作索引。
  - 排除可由先前 Snapshot 答案直接推断后续答案的 QA 组合。

### 2.5 中期训练流程

- **数据配比**：约 30B token 背景语料 + 10B token 编译轨迹数据，共约 40B token；背景语料覆盖代码与仓库、书籍与论文、网页、数学与 STEM、指令与日志。
- **变体**：Retrieval、MultidocQA、State Tracking 单独使用，或按输入 token 数 3:4:3 混合为 TrajLong-All。
- **记录组织**：共享同一上下文的编译样本分组，上下文只放一次，后接 \(M\) 个问答对：\(x=\text{serialize}(c,q_1,y_1,\dots,q_M,y_M)\)。
- **训练配置**：256K 上下文，RoPE base \(1.6\times10^7\) 无额外缩放，全 token 监督；随后统一 SFT 配方。
