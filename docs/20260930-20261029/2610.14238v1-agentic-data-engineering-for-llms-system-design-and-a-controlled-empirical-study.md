## 摘要
LLM数据工程需要通过迭代实验来确定数据选择、奖励和课程如何影响模型学习，这使其成为AI-for-AI（AI4AI）研究的天然场景。智能体能否利用实验反馈逐步改进策略，且所得策略能否提升目标模型在留出数据上的性能？我们研究在固定训练与评估协议下，智能体如何利用实验反馈来制定数据工程策略。我们的智能体数据工程（ADE）框架使智能体能够利用累积发现来推进、修订或组合研究方向。策略根据循环内得分进行选择，并在留出基准上评估。在四个任务——数学与代码数据选择、数学奖励设计以及数学课程学习——中，所选策略在固定训练条件下相较于通用基线取得绝对提升：在AIME25 Pass@32上最高提升13.34%，在四个留出基准上平均提升5.85%。循环内得分在连续实验中有所提升，而留出轨迹表明，后期循环内增益并不总能改善泛化。对研究组织方式与反馈获取途径的比较表明，将证据分析与累积发现相结合更为有利。研究轨迹展示了早期发现如何影响跨研究方向的策略修订与组合。

## Abstract
LLM data engineering requires iterative experimentation to determine how data selection, rewards, and curricula affect model learning, making it a natural setting for AI-for-AI (AI4AI) research. Can agents use experimental feedback to progressively improve strategies, and do the resulting strategies improve target-model performance on held-out data? We study how agents use experimental feedback to develop data-engineering strategies under fixed training and evaluation protocols. Our Agentic Data Engineering (ADE) framework lets agents pursue, revise, or combine research directions using cumulative findings. Strategies are selected by in-loop scores and evaluated on held-out benchmarks. Across four tasks-math and code data selection, math reward design, and math curriculum learning-selected strategies achieve absolute gains over generic baselines of up to 13.34% on AIME25 Pass@32 and 5.85% averaged across four held-out benchmarks under fixed training conditions. In-loop scores improve over successive experiments, while held-out trajectories show that later in-loop gains do not always improve generalization. Comparisons of research organization and feedback access favor combining evidence analysis with cumulative findings. Research trajectories show how earlier findings inform strategy revisions and combinations across research directions.

## 1. 核心问题与研究动机

- **背景**：AI-for-AI（AI4AI）旨在用 AI 系统自动化并改进模型研发过程。LLM 数据工程（数据选择、课程设计、奖励设计）的价值高度依赖目标模型在给定训练条件下的实际学习效果，因此天然需要“提出干预—训练—评估—再决策”的迭代实验闭环。
- **核心问题**：
  - **Q1（研究能力）**：智能体能否利用实验反馈指导后续研究决策，逐步发展出更强的策略？作者强调，真正的自主性应体现在“由证据驱动的科研决策”上，而非仅能执行实验；一个强策略可能只是“多采样择优”的产物。
  - **Q2（有效性）**：智能体开发的策略能否提升目标模型在**未参与研究过程**的留出数据上的性能？反复使用评估反馈可能导致对特定样本或指标的过拟合。
- **研究空白**：现有 AI4AI 系统在干预范围、评估边界、研究决策控制程度上差异很大（如 AutoResearch 允许改训练代码但评估器固定；RSIBench-Data 的选择与最终评估使用同一任务子集；DataMaster 用预定义分数调度分支）。需要一个**固定实验协议 + 闭环选择 + 留出评估**的受控框架，同时考察“策略如何被开发出来”与“策略是否有效”。

## 2. 方法论：ADE 框架

### 2.1 核心思想（两条原则）

- **原则 1**：在固定实验协议下，把研究决策权交给智能体（对应 Q1）。智能体基于累积记忆决定探索、修订、质疑或组合研究方向；Harness 校验动作并控制信息访问；Engine 在任务特定条件下执行被准入的实验。
- **原则 2**：闭环内选择，留出评估（对应 Q2）。仅用闭环分数选择策略与检查点，冻结后在不相交的留出数据上评估，结果不回流到研究过程。

### 2.2 系统结构（Harness 治理的状态机）

- **层级概念**：一个 **Run** 是一次有界研究过程，包含多个 **Plan**（研究方向的承诺），每个 Plan 可含多个 **Trial**（承诺的一次实现与实验评估）。
- **角色分工**：
  - **Coordinator**：基于 Run Memory、Plan 目录、当前排名与预算，提出新方向/回访/组合，输出含假设、机制、预期观察、拒绝条件与控制变量的 Plan。
  - **Builder**：在冻结的 Plan 承诺下实现可执行策略，可在同一 Trial 内做有界反思修订（最多 J 次），但不得改变假设或扩大干预范围。
  - **Analyzer**：**盲审**——不接收 Plan、假设与 Memory，先设计记录级评审（Review Worker 执行），再结合原始证据独立分析。
  - **Plan Summarizer / Run Summarizer**：在独立分析之后做假设裁决，并分别更新 Plan Memory（PM）与 Run Memory（RM）。
  - **Review Worker**：按 Analyzer 设计的 rubric 做记录级判断，无研究决策权。
  - **Engine / Operations**：执行冻结实验、资源调度与恢复，无科学写入权。

### 2.3 关键技术细节

- **实验契约**：每个任务定义策略接口（授权输入、必需输出、约束）。配置 B 固定目标模型、数据与评估划分、训练预算、优化配方、检查点规则、评估器与资源策略；**被准入的策略是唯一由智能体控制的干预**。
- **两级评估预算**（式 1）：
  - 在线评估以较少采样 $K_{online}$ 从训练轨迹中选检查点：$\theta^\star_{p,k}=\arg\max_{\theta\in\Theta_{p,k}} S_{online}(\theta;D_{in},K_{online})$
  - 离线评估以更大预算 $K_{offline}\ge K_{online}$ 给该检查点打分，得到 Trial 的闭环记录 $s_{p,k}$。两者均属闭环，区别于留出评估。
- **不可变实验包**：含闭环分数、选中检查点、执行策略、任务允许的执行/训练/模型行为记录，每条记录带来源 Trial 标识。
- **累积记忆**：PM 保存单一方向的发现、矛盾与未解问题；RM 整合跨 Plan 发现。所有发现保留来源、范围与评估状态，使后续决策可追溯。
- **Harness 强制状态转移**（式 2）：智能体提议动作 $u_t\sim\pi_{agent}(\cdot|View_P(S_t))$，Harness 校验 $u_t\in A_P(S_t)$ 后提交 $(S_{t+1},o_t)=H_P(S_t,u_t)$。角色输入包按信息边界构建；Analyzer 的包明确排除 Plan、假设、Memory、留出记录。
- **版本化提交与队列语义**：Plan 可异步推进，但 Plan 准入与 Run Memory 合并串行化；RM 更新按 FIFO 单写者提交，发布与出队构成一个逻辑提交，恢复后不重复合并；运行中的调用保留冻结输入。
- **恢复机制**（式 15）：重试仅限声明可重试的失败且有剩余恢复预算，新尝试可换物理资源但不得改变逻辑实验 $(x_i,b_i,\psi_i,z_i)$；操作员动作只追加到 ledger，不能改写科学状态。
- **最终选择与留出评估**（式 3）：$b_p=\arg\max_p S_{in}(\tau^\star_p)$，$e_{hold}=Eval_{hold}(\tau^\star_{b_p})$；留出结果被排除在检查点选择、排名、Memory 与后续决策之外。
