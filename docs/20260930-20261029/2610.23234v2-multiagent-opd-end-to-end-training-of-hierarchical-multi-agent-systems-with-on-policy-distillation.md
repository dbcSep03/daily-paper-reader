## 摘要
在分层多智能体系统中，Leader 负责任务分配，子智能体负责执行任务。联合训练 Leader 与子智能体较为困难，因为最终答案只能为子智能体提供间接反馈。LLM 评判器可以给子智能体的表现打分，但这些分数取决于评判器自身对子智能体回复质量的评估。我们提出 MultiAgent-OPD，将同策略蒸馏与强化学习相结合，端到端联合训练一个共享参数的 Leader-Searcher-Answerer 团队。我们首先在 Searcher-Answerer 工作流中利用答案正确性训练一个 Teacher。在团队训练过程中，冻结的 Teacher 对学生生成的搜索与摘要 token 进行打分，为 Searchers 提供局部过程监督；同时，Leader 从团队成功中学习，Answerer 从候选答案正确性中学习。在七个数据集上，训练后的系统达到 38.68% 的 macro avg@4，比 Prompted Critic 高出 4.06 个百分点，比经过训练的级联多智能体系统 C-MAS + RL 高出 2.61 个百分点。该团队还能在四次尝试内解决更多问题。

## Abstract
In a hierarchical multi-agent system, a Leader assigns tasks and subagents carry them out. Jointly training the Leader and the subagents is difficult because a final answer gives only indirect feedback to the subagents. An LLM judge can score the performance of the subagents, but these scores depend on the judge's own assessment of the quality of subagents' responses. We present MultiAgent-OPD, which combines on-policy distillation with reinforcement learning to jointly train a shared-parameter Leader-Searcher-Answerer team end to end. We first train a Teacher in a Searcher-Answerer workflow using answer correctness. During team training, the frozen Teacher scores student-generated search and summary tokens to provide local process supervision for the Searchers, while the Leader learns from team success and the Answerer from candidate correctness. Across seven datasets, the trained system reaches 38.68% macro avg@4, exceeding Prompted Critic by 4.06 percentage points and C-MAS + RL, the trained cascaded multiagent system, by 2.61 percentage points. The team also solves more questions within four attempts.

# MultiAgent-OPD 论文总结

## 1. 核心问题与研究动机

- **背景**：在分层多智能体系统（Leader–Searcher–Answerer）中，Leader 负责任务分解与分派，Searcher 负责检索与摘要，Answerer 负责整合回答。三者共享同一目标，但各自承担不同职能。
- **核心痛点**：联合端到端训练困难。最终答案只对子智能体（尤其是 Searcher）提供**间接反馈**：
  - 一份有用的检索报告可能因 Leader 未选用或 Answerer 推理失败而得不到正向奖励；
  - 用 LLM 评判器给子智能体打分虽然能提供局部监督，但分数依赖评判器自身能力，存在偏差与推理错误；
  - 单一子任务分数也无法指导“产生该报告的整条搜索决策序列”。
- **现有工作不足**：PARL 只优化 Leader、冻结子智能体；M-GRPO 虽联合训练，但依赖 LLM 评判的子任务打分；已有 OPD 搜索工作（SD-Search、OPDSearch+ 等）只训练**单个**搜索智能体，不涉及任务委派。
- **整体含义**：论文主张按“各角色与最终目标的关系”匹配学习信号——Leader/Answerer 用结果奖励，Searcher 用来自任务训练 Teacher 的 token 级同策略蒸馏（OPD）过程监督，从而实现分层团队的端到端联合训练。

## 2. 方法论

### 核心思想
两阶段框架，将 OPD 嵌入分层多智能体 RL：
- **Stage I**：在更简单的 Searcher–Answerer 级联工作流上训练一个 Teacher；
- **Stage II**：冻结 Teacher，为分层学生团队的 Searcher 提供 token 级局部监督，Leader 与 Answerer 保留结果型 RL 目标。三个角色**共享同一模型参数**，推理时只需学生模型。

### Stage I：训练 Teacher
- 工作流：Searcher 接收问题→检索→写报告；Answerer 依据报告作答。
- 奖励设计：
  - Answerer：$R_{A,i,j}=c_{i,j}$（候选答案的归一化精确匹配分）；
  - Searcher：$R_{S,i}=0.9\,R_{EM,i}+0.1\,b_{S,i}$，其中 $b_{S,i}$ 为行为奖励（1 次搜索后总结得 0.5，≥2 次得 1，否则 0）；
  - 格式非法输出给 −1。
- 用 GRPO 组内归一化优势 + PPO 裁剪目标更新；训练后的策略既作为 **C-MAS + RL 基线**评估，也被冻结为 Teacher $\pi_T$。

### Stage II：角色特定优势的团队训练
- **团队轨迹采样**：每个问题采样 $G$ 条完整工作流轨迹（含多波 Searcher、Leader 多轮委派、Answerer 多候选）。
- **Leader**：$R_{L,i}=0.9\,R_{EM,i}+0.1\,R_{assign,i}$，$R_{assign}=\min(C_{tool},6)/6$，$C_{tool}$ 为含至少一次搜索动作的环境步数；按 Eq.(1) 组内归一化得 $\hat A^{GRPO}_{L,i}$。
- **Answerer**：$R_{A,i,j}=c_{i,j}$，在父工作流内归一化得 $\hat A^{GRPO}_{A,i,j}$。
- **Searcher（OPD）**：对每个 Searcher 响应，冻结 Teacher 在**与学生相同的角色提示、子任务、检索段落和已生成前缀**上前向打分；token 级优势为
  $$\hat A^{OPD}_{S,t}=\beta\,M_t\log\frac{\pi_T(a_t\mid h_t)}{\pi_{old}(a_t\mid h_t)},\quad \beta=0.01$$
  其中 $M_t$ 仅在 Searcher 生成的 token 上为 1（检索段落、padding 被 mask）。该 log-ratio 等价于反向 KL 蒸馏的负梯度优势，**不是**对最终答案的因果贡献估计。
- **损失组合**：PPO 裁剪目标 + 熵奖励；Leader/Answerer 额外加系数 $10^{-3}$ 的 KL 惩罚（朝 $\pi_T$），Searcher 不加额外 KL；每个 token 取生成它的角色的优势（Eq.7）。

### 关键设计动机
- Searcher 若用结果奖励，同轨迹内所有 Searcher 共享同一优势，且当 $G$ 条轨迹结果相同（全对或全错）时优势为零 → 无学习信号；OPD 让**每个 Searcher token 都有信号**。
- Teacher 在学生生成的前缀上打分，因此当 Leader 改变任务划分时，监督能跟随新子任务状态。

## 3. 实验设计

### 数据与场景
- **训练**：Natural Questions（79,168 条）+ HotpotQA（90,447 条）。
- **测试**：固定 5,000 题，来自 7 个开放域 QA 基准——NQ、TriviaQA、PopQA（各 812）、HotpotQA、2WikiMultiHopQA、MuSiQue（各 813）、Bamboogle（125）；覆盖单跳与多跳。

## 6. 主要结论与发现

- **主结果**：MultiAgent-OPD 达 **38.68% macro avg@4**，超过 Prompted Critic **+4.06pp**（95% CI [+2.98, +5.12]）、C-MAS + RL **+2.61pp**（[+1.49, +3.73]）、最强外部 RL 智能体 Tree-GRPO（37.37%）**+1.31pp**；macro pass@4 达 **48.73%**（外部最高 47.64%）。
- **覆盖与一致性**：4/4 全对率 29.27%，高于 C-MAS + RL（27.05%）与 Prompted Critic（23.24%）。
- **分层结构本身有效**：H-MAS base（28.60%）比 C-MAS base（25.09%）高 3.51pp，四个多跳数据集全部更优。
- **消融关键发现**：
  - Searcher 改用结果奖励 → **搜索行为崩溃**：测试集 20,000 条工作流中**零次搜索动作**，macro avg@4 跌至 17.78%（比 H-MAS base 还低 10.82pp）；训练中 step 300→400 无搜索比例从 0.5% 跳到 100%，EM 从 26.0% 降到 21.8%——说明最终答案奖励无法维持分层系统中的检索行为；
  - 用基座模型替代任务训练 Teacher → 29.50%（−9.18pp），说明 Teacher 的**任务训练**而非仅 token 级蒸馏目标本身关键；
  - 移除 Searcher 直接监督 → 29.82%（−8.86pp），说明仅靠共享参数间接更新不足。
- **资源代价**：相比 Prompted Critic，搜索动作 +21.4%、输入 token +35.2%，但输出 token 从 885 降至 697；C-MAS + RL 以最少搜索达到 36.07%，说明工作负载本身不能解释排名。
- **定性案例**：MultiAgent-OPD 能把 “Athlete”

…（承上）这类宽泛指代线索，经 Leader 分解为“先定位具体人名/项目、再核对其成绩或所属赛事”的可检索子查询，并在证据不足时追加检索；而 Prompted Critic 的 Searcher 倾向于一次检索后即写报告，C-MAS + RL 则出现查询重复、与子问题不匹配的情况。第二个案例（Appendix D）展示多跳问题中 Leader 依据中间证据**改写后续子任务**、Searcher 随之调整查询的过程，用以说明 Stage II 的 OPD 监督能跟随“被重新划分的子任务状态”而非固定在原始问题上。

## 7. 局限与风险

- **可复现性信息不足**：未报告 GPU 型号/数量、训练时长与总步数对应的算力开销；检查点选择依赖验证峰值，主表仅报单一检查点，缺跨训练种子的方差。
- **Teacher–Student 工作流分布偏移**：Stage I 的 Searcher 面对的是**原始问题**，Stage II 的 Searcher 面对的是 **Leader 分派的子任务**。虽然论文强调 Teacher 在学生前缀上打分可缓解该问题，但 token 级 log-ratio 只保证“局部写法像 Teacher”，**不保证子任务本身被正确理解或检索到关键证据**；若 Leader 分派了错误子任务，Searcher 会被高置信度地蒸馏到错误方向上。
- **OPD 目标本身的信息局限**：作者明确指出该优势是反向 KL 蒸馏的负梯度，**不是对最终答案因果贡献的估计**，因此无法区分“有用的检索”与“看似合理但无关的检索”；`β=0.01` 为固定超参，未见敏感性分析。
- **角色共享参数的相互干扰**：三角色共用一套权重，论文只做了“移除 Searcher 直接监督”这一方向的消融，未分析角色间能力竞争（如 Searcher 蒸馏信号是否削弱 Leader/Answerer 的推理能力）。
- **评测范围**：单一 4B 主干、单一 E5 检索器、英文开放域 QA；指标为归一化精确匹配，忽略语义等价答案；与外部 RL 基线的比较为描述性（无配对区间、未在匹配的检索/token 预算下对比）。
- **对照基线有限**：Searcher 的局部监督只与“LLM 评判器打分”和“结果奖励”比较，未与过程奖励模型（PRM）、人工标注子任务质量或更强 Teacher 对比。

## 8. 启示与可迁移结论

1. **学习信号应按“角色与最终目标的关系”分配**：直接对结果负责的角色（Leader、Answerer）适合结果型 RL；中间角色（Searcher）适合过程监督。这是本文最具方法论价值的观点，可迁移到其他分层智能体（如代码生成中的规划者/检索者/执行者）。
2. **分层结构 + 端到端训练是两个独立增益**：H-MAS base 已优于 C-MAS base（+3.51pp），而 OPD 在其上再增益，说明“结构红利”与“训练红利”不冲突、可叠加。
3. **子智能体的结果奖励会导致行为崩溃，而非仅仅学习缓慢**：诊断实验中 Searcher 改用结果奖励后训练中途（step 300→400）无搜索比例从 0.5% 跃升至 100%，属于**策略坍塌**而非渐进退化，提示多智能体 RL 中“共享同一结果优势”的设计存在结构性风险。
4. **教师的任务训练比蒸馏目标本身更关键**：基座模型作 Teacher 时掉 9.18pp，说明 OPD 的效果上限由 Teacher 的领域能力决定，蒸馏只是传输通道。
5. **过程监督不必引入额外标注或评判器**：用同构但更简单的工作流（Stage I 级联）自举 Teacher，是一种低成本获取 token 级监督的可行路径。

## 9. 总体评价

- **贡献**：提出“角色特定优势”的分层多智能体联合训练框架，把 OPD 从单智能体场景扩展到任务委派场景，并以“结果奖励导致搜索行为崩溃”的清晰诊断证据支撑设计选择，问题定位与方法动机的对应关系紧密。
- **证据强度**：主实验规模较大（7 数据集、5,000 题、avg@4/pass@4、bootstrap 置信区间），内部对照（Prompted Critic 仅 Searcher 信号不同）设计较严谨；主要短板是**单检查点、单种子、单主干**，以及外部基线缺配对比较，因此 +1.31pp 对最强外部系统的优势应视为**边际但方向一致**的证据，而 +4.06pp 对 Prompted Critic 的优势更可信。
- **写作与透明度**：明确声明 OPD 优势的语义边界（非因果贡献）、公开格式失败上界与资源消耗，属较诚实的报告风格；算力信息缺失是主要减分项。
- **适用边界**：结论最适用于“有明确可验证最终答案 + 可检索外部知识 + 中等规模主干”的分层 QA 场景；对开放式、无唯一答案的任务，结果奖励本身失效，本文方案需重新设计。
