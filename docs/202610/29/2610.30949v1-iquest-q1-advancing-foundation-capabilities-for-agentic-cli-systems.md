## 摘要
我们提出 IQuest-Q1，一种稀疏混合专家（MoE）智能体基础模型，总参数 320B（激活参数 15B）。IQuest-Q1 通过三阶段过程开发：（1）稳定高效的预训练，将 Stable SplitNorm、Muon 和 muP 与两阶段课程相结合，其中第二阶段增加代码数据混合比例，并在安全学习率与最优学习率之间保持较大的稳定裕度；（2）细粒度中期训练，跨领域和格式扩展数据混合，并逐步扩展上下文；（3）多脚手架与多版本后训练，在不同脚手架中结合 SFT、领域专用 RL 和 MOPD，以整合互补的训练信号并增强智能体编码能力。此外，模型合并结合了不同专家以及来自不同阶段的检查点，同时缓解其参数更新之间的冲突。由此得到的 IQuest-Q1 在编码和通用任务上均展现出能力。我们将 IQuest-Q1 作为开源模型发布，以支持社区的研究与开发。

## Abstract
We present IQuest-Q1, a sparse Mixture-of-Experts (MoE) agentic foundation model with 320B total parameters (15B activated). IQuest-Q1 is developed through a three-stage process: (1) stable and efficient pre-training, combining Stable SplitNorm, Muon, and muP with a two-stage curriculum whose second stage increases the coding-data mixture, preserving a wide stability margin between safe and optimal learning rates; (2) fine-grained mid-training, expanding the data mixture across domains and formats and progressively extending the context; and (3) multi-scaffold with multi-version post-training, combining SFT, domain-specialized RL, and MOPD across various scaffolds to integrate complementary training signals and strengthen agentic coding capabilities. Furthermore, model merging combines different experts and checkpoints from different stages while mitigating conflicts among their parameter updates. The resulting IQuest-Q1 demonstrates capabilities in both coding and general tasks. We release IQuest-Q1 as an open-source model to support community research and development.

## 1. 核心问题与研究动机

- **背景**：基于 LLM 的智能体通过“推理—行动—环境交互”的迭代循环完成任务，而命令行界面（CLI）已成为语言模型访问外部系统、调用工具、读写文件与执行代码最通用的接口之一。因此，更强的智能体能力在很大程度上依赖更强的 CLI 能力。
- **核心问题**：如何构建一个在真实 CLI 环境中可靠工作、同时兼顾编程与通用任务能力的**开源智能体基础模型**，并在训练稳定性、数据配比、跨脚手架泛化等环节系统性地解决工程与算法挑战。
- **整体含义**：作者提出 IQuest-Q1（320B 总参数、15B 激活参数的稀疏 MoE 模型），目标是覆盖软件工程、通用任务执行、长程推理与网络安全等场景，并针对真实 CLI 使用做优化（可靠工具调用、跨 agent harness 鲁棒）。模型以开源形式发布，同时被嵌入作者内部的“人在环上”（human-on-the-loop）迭代开发流程，探索递归自我改进（RSI）的实践路径。

## 2. 方法论

### 2.1 核心思想
采用**三阶段流水线**逐步发展通用知识、长上下文与智能体 CLI 能力：
1. **稳定高效预训练**：Stable SplitNorm + Muon + μP + 两阶段课程（第二阶段提高代码数据比例）。
2. **细粒度中期训练**：跨领域/格式扩展数据混合，渐进扩展上下文（32K→128K→512K）。
3. **多脚手架、多版本后训练**：SFT → 领域专用 RL → 多教师同策略蒸馏（MOPD），最后进行**模型合并**整合不同专家与不同阶段检查点。

### 2.2 关键技术细节

- **架构**（表 1）：
  - 88 层 Transformer，隐藏维度 3072；48 个 Q 头 / 8 个 KV 头，头维度 128。
  - 混合注意力：前 2 层与后 2 层为全注意力（FA），中间层按 **3 层 SWA + 1 层 FA** 循环；SWA 窗口 4096。
  - Partial RoPE 仅作用于每个头 32 维；SWA 与 FA 的 RoPE base 分别为 10,000 与 1,000,000。
  - 查询感知 Sink Attention（所有层启用）；QKNorm + QKNorm Clip（仿射参数上限 10）。
  - 第一层用稠密 FFN（中间维 12288）以缓解专家负载不均衡，其余层为稀疏 MoE：256 个路由专家、每 token 激活 8 个、专家中间维 1536；SwiGLU。
  - 词表 160,000，输入嵌入与输出权重不共享。
  - 预训练使用 2 个 MTP 层（损失权重 0.3）；推理时将第一层改造为**递归 drafter**（EAGLE-3 式，7 个 drafting step，SWA 窗口 512），第二层在专门训练阶段丢弃。

- **Stable SplitNorm**：残差流进入注意力子层时做 RMSNorm，进入 FFN 时保持未归一化，即
  - `z = RMSNorm(x)`，`h = z + Attention(z)`，`y = h + FFN(RMSNorm(h))`；
  - 进一步对注意力输出加 RMSNorm（`h = z + RMSNorm(Attention(z))`），首层使用 SandwichNorm，防止激活爆炸并提升深度利用率。

- **μP 与优化器**：宽度与深度方向的学习率迁移（4× 宽度、4× 深度范围验证）；在隐藏宽度 896、18 层的代理模型上搜索学习率后零样本迁移到目标规模。Muon 用于除嵌入、LM head、归一化参数与 MoE 路由外的所有参数（动量 0.95，正交化更新缩放 `0.2√max(m,n)`），其余用 Adam（β1=0.9, β2=0.95, ε=1e-15）；权重衰减 0.1；warmup-stable-decay 学习率调度（预热至 6e-4，Stage 2 末降至 2e-4，中期训练末降至 6e-5）。

- **缩放稳定性框架（CMS）**：定义稳定裕度 `H_N = log(η_safe(N)/η_opt(N))`，当 `η_opt(N_CMS) = η_safe(N_CMS)` 时得到**临界模型规模**；外推得到 `N_act_CMS ≈ 572B`、`N_total_CMS ≈ 12T`，说明该架构与训练配方仍有较大稳定扩展空间。

- **中期训练**：
  - 数据三类：高质量自然语料、QA 对、智能体轨迹；采用适配中期训练的 chat template，保留推理与工具调用相关特殊 token。
  - **Token 级损失掩码**：直接对单个 token 指定掩码，解耦数据格式与损失计算。
  - 上下文经 32K→128K→512K 三阶段扩展；全局注意力 RoPE base 从 500,000 升至 1,000,000；学习率采用单一 cosine 衰减，阶段切换时迁移权重并重置优化器状态。
  - 智能体数据：以精选轨迹为行为锚点，从兼容代码仓库构建可执行容器化实例（超过 100 万个），rollout 后保留有效完整轨迹。

- **后训练**：
  - **任务合成**：通用（RapidAPI、Smithery、公开技能、工作区文件，参照 SOC 职业分类）、推理（文档驱动流水线）、编码（GitHub 仓库 + 工业数据，多版本 Claude Code / Codex 脚手架，agent-judge 循环校验可执行性、泄漏与一致性）。
  - **奖励黑客缓解**：环境准备（清理 Git 历史、隔离环境）、执行时检查（网络限制、工具调用拦截）、轨迹审计（规则 + LLM 评判）；针对 SWE 类、Terminal-Bench、ProgramBench 做差异化防护。
  - **SFT**：两阶段（Stage 1 240B+ tokens，Stage 2 50B+ tokens），学习率 5e-5 / 1.5e-5，cosine 衰减，序列打包 + 注意力掩码。
  - **环境中心 RL**：多脚手架、多版本 episode（Claude Code、Codex 及其版本），GRPO 在同任务同脚手架同评估器版本下比较多次 rollout；奖励含终端正确性、分段进度奖励与计算/约束/奖励黑客惩罚；失败归因区分策略错误、环境/脚手架故障与评估器故障；TITO 管线做 token 级更新。
  - **MOPD**：学生从 SFT Stage 2 初始化，从 4 个冻结专家（终端交互/用户体验、多脚手架、长程编码与网络安全、通用智能体）蒸馏；采用裁剪的蒸馏优势
    - `ã_{i,t} = clip(log(q_{d_i}(y_{i,t}|h_{i,t}) / p_k(y_{i,t}|h_{i,t})), -c, c)`，
    - 优化长度归一化代理损失 `L_k(θ) = -(1/B) Σ_i (m_i/T_i) Σ_{t∈A_i} ã_{i,t} log p_θ(y_{i,t}|h_{i,t})`，其中 `m_i=0` 表示重复 rollout、`m_i=1` 否则；rollout、上下文、优势与掩码在微分时固定。
  - **模型合并**：从 SFT Stage 1 出发，跨阶段与专家分支交错进行残差合并；每次合并以指定参考检查点为基准计算参数增量，按预设权重与全局 ℓ2 范数校准后加回参考参数。
  - **基础设施**：best-fit 序列打包（前瞻窗口 2BS）、跨数据并行副本重排以平衡长文档计算、SWA 线性上下文并行（halo 交换与计算重叠、LSE 重归一化合并边界查询）、分布式训练正确性不变量检查、异步 MOPD（教师权重按需加载与预取）。
