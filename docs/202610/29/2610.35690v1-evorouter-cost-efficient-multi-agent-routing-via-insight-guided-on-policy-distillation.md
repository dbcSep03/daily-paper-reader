## 摘要
利用多智能体系统大规模服务网络查询，需要联合配置大语言模型、协作模式、智能体数量、交互轮次和技能。然而，由此产生的配置空间呈组合式增长，而稀疏的执行奖励难以为相互依赖的规划决策提供细粒度监督。我们提出 EvoRouter，一个由洞见引导的同策略蒸馏驱动的自演化多智能体路由框架。专用专家会定期将跨任务的配置轨迹中的性能-成本反馈综合为可复用的条件路由洞见，涉及能力需求、资源扩展带来的收益以及配置选择之间的交互。特权教师将这些不断演化的洞见与当前执行反馈相结合，通过同策略蒸馏为路由器自身的规划轨迹提供密集的 token 级监督。成本感知强化学习联合优化任务性能和计算成本。这些训练信号共同将执行洞见内化到路由策略中。更新后的策略会生成新的轨迹，以支持后续的洞见提取，从而形成执行驱动的自我改进循环。我们在涵盖五个领域的 19 个域内数据集和两个域外基准上评估 EvoRouter。EvoRouter 的平均域内准确率达到 68.69%，比最强的路由基线高出 7.23 个百分点，同时将推理计算成本降低 50.95%。我们的代码已开源于 https://github.com/CenYangtze/EvoRouter。

## Abstract
Serving web queries at scale with multi-agent systems requires jointly configuring large language models, collaboration modes, agent counts, interaction rounds, and skills. However, the resulting configuration space grows combinatorially, while sparse execution rewards provide limited fine-grained supervision for interdependent planning decisions. We propose EvoRouter, a self-evolving multi-agent routing framework driven by insight-guided on-policy distillation. A dedicated expert periodically synthesizes performance-cost feedback from configuration trajectories across tasks into reusable conditional routing insights about capability requirements, returns from resource scaling, and interactions among configuration choices. A privileged teacher combines these evolving insights with current execution feedback to provide dense token-level supervision for the router's own planning trajectories through on-policy distillation. Cost-aware reinforcement learning jointly optimizes task performance and computational cost. Together, these training signals internalize execution insights into the routing policy. The updated policy generates new trajectories that support subsequent insight extraction, forming an execution-driven self-improvement loop. We evaluate EvoRouter on 19 in-domain datasets spanning five domains and two out-of-domain benchmarks. EvoRouter achieves an average in-domain accuracy of 68.69%, outperforming the strongest routing baseline by 7.23 percentage points while reducing inference compute cost by 50.95%. Our code is open-sourced at https://github.com/CenYangtze/EvoRouter.

## 1. 核心问题与整体含义

- **研究背景**：随着 LLM 智能体在 Web 服务中的广泛应用（信息检索、复杂推理、问题求解），多智能体系统（MAS）逐渐成为主流形态。此时"路由"不再只是从模型池中选一个模型，而是要**联合决定**：使用哪些 LLM、采用何种协作模式（IO/CoT/Reflection/Chain/FullConnected/Debate 等）、配置几个智能体、交互几轮、每个智能体承担什么子任务和技能。
- **核心矛盾一：配置空间组合爆炸**。上述维度的联合选择导致配置空间呈组合式增长，穷举评估在计算上不可行；且单一执行轨迹只能反映某一特定配置下的结果，难以判断某项决策是必要、冗余还是次优。
- **核心矛盾二：稀疏奖励难以监督细粒度规划**。现有 RL 路由方法仅从最终任务成败与成本获得稀疏奖励，而一次完整 MAS 配置涉及多个相互耦合的规划决策，终端奖励无法告诉路由器"哪一步决策有效、哪一步浪费资源、应如何调整"。
- **核心问题**：如何将配置与执行结果中的经验，蒸馏为关于**条件依赖关系**的可复用知识，并内化到路由器的**执行前规划策略**中，从而改善准确率–成本的系统级权衡。
- **整体含义**：论文提出 EvoRouter，将"经验演化"与"策略学习"打通——执行产生轨迹，轨迹被专家提炼为洞见，洞见通过同策略蒸馏变成 token 级监督信号，更新后的策略再产生新轨迹，形成**执行驱动的自演化闭环**。

## 2. 方法论

### 2.1 核心思想
以三条实证洞见为分析框架，构建"**洞见提取 → 特权蒸馏 → 策略内化 → 新轨迹采样**"的递归自我改进（RSI）循环，并用成本感知 RL 联合优化性能与开销。

### 2.2 三条路由洞见（来自预备实验）
1. **Where to Scale（任务依赖性）**：不同任务对资源扩展的收益方向不同。例如从 `mβ+IO` 切换到 `mα+FullConnected`，多模态任务成功率提升 13.1 点，而 QA 任务下降 5.0 点。
2. **How Much to Scale（边际收益递减）**：不同模型与协作策略在不同交互轮次/智能体数量处达到性能峰值，继续扩展会增加成本甚至降低成功率。
3. **What to Combine（配置交互性）**：单资源的有效性依赖整体配置。例如全 `mβ` 配置在 FullConnected 下优于全 `mα`，但在 Debate 下反转，且后者可减少 79.8% 的 MAS FLOPs。

### 2.3 问题形式化
- 路由器将任务 $q$ 映射为配置 $P = (c, r, \{(u_j, m_j, s_j, p_j)\}_{j=1}^{n})$，其中 $c$ 为协作模式、$r$ 为交互轮次、$n$ 为智能体数，每个智能体由标识、模型、技能、子任务定义。
- 环境执行返回结果 $o \sim \mathcal{E}(\cdot|q,P)$，验证器给出 $s(\tau)\in\{0,1\}$，执行成本为 $C(\tau)$，任务预算为 $B(q)$。
- 优化目标：$\pi^\star = \arg\max_\pi \mathbb{E}_{q,\tau}[U(s(\tau), C(\tau)/B(q); \lambda_C)]$。

### 2.4 训练流程（四阶段）

**（1）监督初始化（SFT）**
- 用强 LLM（DeepSeek-V4-Pro）作为 bootstrap 路由器采集轨迹，仅保留格式合法且答案正确的样本构成 $\mathcal{D}_{SFT}$，训练 2 个 epoch。
- 损失为标准下一 token 负对数似然，仅对路由器生成的 token 计算，prompt 与环境反馈被 mask。
- 该策略同时作为后续 KL 正则的**冻结参考策略** $\pi_{ref}$。

**（2）成本感知策略优化（RL）**
- 奖励设计：$R(\tau) = R_{perf} - \lambda_C \cdot R_{cost}$，其中 $R_{perf}=s(\tau)\in\{0,1\}$，$R_{cost}=\log_2(1+C(\tau)/B(q))$。
- 将加权成本惩罚截断在 $c_{max}\in[0,1)$，保证成功轨迹奖励至少为 $1-c_{max}>0$，失败轨迹奖励非正，从而**严格分离成功/失败奖励区间**。
- 每个任务采样 $G$ 条 rollout，计算组内归一化优势 $A_{q,i}$，使用组相对策略梯度（类 GRPO）更新。
- 加入 token 级 KL 惩罚防止策略漂移：$\mathcal{L}_{KL}$ 基于 $\pi_{ref}/\pi_\theta$ 概率比。

**（3）洞见引导的同策略蒸馏（OPD）**
- **递归洞见整合**：专家 $\mathcal{F}$（DeepSeek-V4-Pro）周期性对最近 rollout 批次执行三步：① 规则归纳（对比同类任务成功/失败与成本谱系）；② 前置条件精炼（通过细化任务难度/领域边界消解经验冲突）；③ 容量剪枝（合并冗余、限制 $|\mathcal{I}|\le 8$ 与总长 ≤6144 字符）。更新式为 $\mathcal{I}_{k+1}=\mathcal{F}(\mathcal{I}_k,\mathcal{B}_k)$。
- **特权教师监督**：冻结教师 $\pi_\phi$ 接收额外特权信息 $z_i=(\mathcal{I}, P_i, o_i, s(\tau_i))$，与学生共享同一上下文与前缀。
- **蒸馏目标**：在共享词表 $\Omega$ 上最小化反向 KL（MiniLLM 式）：$D_{i,t}=D_{KL}(p^S_{i,t} \| \text{sg}[p^T_{i,t}])$，其中 sg 为停止梯度。
- **Token 级加权**：分别对 `<plan>` 与 `<analysis>` 标签内 token 计算蒸馏损失，用系数 $\alpha=0.25$ 加权。

**（4）联合优化**
- 总损失：$\mathcal{L}(\theta)=\mathcal{L}_{RL}(\theta)+\lambda_D\mathcal{L}_{OPD}(\theta)+\beta\mathcal{L}_{KL}(\theta)$，超参 $\beta=0.001$、$\lambda_D=0.03$。
- 更新后的策略继续采样新轨迹，供下一轮洞见提炼，闭环成立。
- **推理阶段无需特权信息**，教师与专家仅在训练时使用。

## 6. 主要结论与发现

1. **准确率显著领先**：EvoRouter-4B 域内平均 68.69%，EvoRouter-8B 达 71.23%；相比最强基线 RCR-Router（61.46%）提升 **7.23 个百分点**。
2. **成本大幅降低**：EvoRouter-4B 平均 MAS 成本 15,280 FLOPs units，比 RCR-Router **降低 50.

……降低 50% 以上（即成本约为 RCR-Router 的一半左右）。这组结果说明 EvoRouter 的优势并非“用更多算力换准确率”，而是在**更低的 MAS 执行成本**下取得更高准确率。

3. **Pareto 前沿占优**：在准确率–成本平面上，EvoRouter 的三个变体整体位于基线方法的 Pareto 前沿左上方；即使把路由器自身的推理开销计入总成本，其“单位成本收益”仍优于多数多智能体路由基线。这一点对实际部署尤为关键，因为路由器的开销在小模型（4B）场景下不可忽略。

4. **消融验证各组件必要性**：移除洞见（w/o Insights）后性能下降最明显，说明**结构化经验知识**是收益的主要来源；移除 OPD 后性能次之下降，表明“特权教师 → token 级蒸馏”确实把洞见转化成了可执行的规划行为；同时移除 RL 与 OPD 的退化进一步扩大；完全退化为纯 SFT 时性能最低。该单调退化序列支持“洞见—蒸馏—RL”三者互补而非冗余的设计主张。

5. **演化动态呈持续改进**：在 10 次演化迭代的曲线中，性能随迭代上升而成本趋于稳定或下降，说明洞见库在迭代中逐步收敛为“高价值、低冗余”的条件性规则，而非简单堆积；不同 backbone（4B/8B/Llama-8B）均呈现类似趋势，说明闭环机制对模型规模不敏感。

6. **成本敏感度可控**：随 $\lambda_C$ 从 0 增至 0.2，整体成本单调下降、准确率小幅回落，且不同领域的最优 $\lambda_C$ 不同——多模态与检索类任务对成本惩罚更敏感，数学/知识类任务在高 $\lambda_C$ 下仍能保持较好性能。这表明 EvoRouter 学到的不是单一固定配置，而是**随预算条件调整扩展程度**的策略。

7. **零样本泛化成立**：在同时替换 LLM 池、协作模式池与技能池的设置下，EvoRouter 仍优于在旧资源池上训练的基线路由方法，说明其内化的是**关于“任务难度—资源匹配—协作模式”的条件依赖知识**，而非对特定模型名或技能名的记忆。这是论文最具方法学价值的发现之一。

8. **案例可解释**：数学题案例显示，路由器会先选择较低成本的 Chain/Reflection 配置，在检测到推理链断裂或验证失败风险信号后才升级到 FullConnected 并调用更强模型，体现了“按需扩展”的决策逻辑；洞见示例则展示了从失败轨迹中提炼出的前置条件（如“多跳检索任务中 Debate 在轮次 >3 时收益为负”）如何被后续规划复用。

## 7. 局限与讨论

- **强模型依赖**：SFT bootstrap 与洞见提炼均依赖 DeepSeek-V4-Pro，蒸馏教师依赖 Qwen3-32B / Llama-3.1-70B。若缺少同级强模型，闭环的“经验质量上限”会明显受限，论文未讨论弱专家条件下的退化情况。
- **成本度量偏差**：以归一化 FLOPs 作为成本代理，忽略了实际部署中的延迟、显存占用、API 计费与并行效率差异；对交互轮次多的协作模式（如 Debate）可能系统性低估其真实开销。
- **训练开销未量化**：未报告完整演化循环的 GPU 小时数与 wall-clock 时间，也未单独计量教师推理与洞见提炼的额外成本，影响可复现性与“性价比”结论的完整性。
- **洞见库容量约束**：$|\mathcal{I}|\le 8$ 与长度上限 6144 字符是工程性剪枝，论文未给出该上限的敏感性分析，过小的库可能丢失长尾经验，过大的库则可能引入冲突规则。
- **任务域偏置**：域外仅覆盖代码与逻辑推理两类，未覆盖开放式生成、长程工具使用等场景，泛化结论的边界仍需扩展验证。
- **评测公平性细节**：多模态任务中对不支持图像的模型使用固定占位符，可能使部分基线的多模态表现被低估；同时基线多以 GLM-5 为 backbone，而 EvoRouter 使用 4B/8B 路由器，比较维度是“策略质量”而非“端到端同规模对比”，需在解读提升幅度时保持谨慎。

## 8. 总体评价与启示

- **问题定位准确**：论文抓住了多智能体路由中“配置组合爆炸 + 稀疏奖励”的双重难点，并将其转化为“经验如何被蒸馏为可复用条件知识”的学习问题，问题建模清晰。
- **方法设计自洽**：以“执行 → 洞见 → 特权蒸馏 → 策略内化 → 新执行”的递归自我改进闭环串联 SFT、RL 与蒸馏，三条实证洞见（Where / How Much / What to Combine）为设计提供了可解释的动机支撑，而非纯粹堆叠技巧。
- **实验证据较充分**：21 个数据集、五类基线、消融/敏感度/演化/泛化/案例多角度验证，结论方向一致，主结论可信度较高。
- **可迁移启示**：把“专家对轨迹的事后分析”转化为“token 级特权监督”，是一种在**稀疏终端奖励**场景下注入结构化先验的通用范式，可推广到工具调用编排、检索增强流程设计等需要联合决策的任务。
- **改进空间**：降低对强专家的依赖（如用小模型自蒸馏或多专家投票提炼洞见）、引入更贴近部署的成本模型（延迟/费用）、以及给出洞见库容量的敏感性分析，是后续工作最值得推进的三个方向。
