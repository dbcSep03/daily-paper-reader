## Abstract 

Serving web queries at scale with multi-agent systems requires jointly configuring large language models, collaboration modes, agent counts, interaction rounds, and skills. However, the result-ing configuration space grows combinatorially, while sparse ex-ecution rewards provide limited fine-grained supervision for in-terdependent planning decisions. We propose EvoRouter , a self-evolving multi-agent routing framework driven by insight-guided on-policy distillation. A dedicated expert periodically synthesizes performance–cost feedback from configuration trajectories across tasks into reusable conditional routing insights about capability re-quirements, returns from resource scaling, and interactions among configuration choices. A privileged teacher combines these evolv-ing insights with current execution feedback to provide dense token-level supervision for the router’s own planning trajectories through on-policy distillation. Cost-aware reinforcement learning jointly optimizes task performance and computational cost. To-gether, these training signals internalize execution insights into the routing policy. The updated policy generates new trajectories that support subsequent insight extraction, forming an execution-driven self-improvement loop. We evaluate EvoRouter on 19 in-domain datasets spanning five domains and two out-of-domain benchmarks. EvoRouter achieves an average in-domain accuracy of 68.69%, out-performing the strongest routing baseline by 7.23 percentage points while reducing inference compute cost by 50.95%. Our code is open-sourced at https://github.com/CenYangtze/EvoRouter.

## 1 Introduction 

Agents powered by large language models (LLMs) are rapidly ex-panding the capabilities of Web services [29, 35], from information seeking to complex reasoning and problem solving [21, 38]. LLM routers have emerged as a key component of agentic infrastructure, selecting suitable models for individual queries to balance response quality and inference cost [4, 12, 36, 47]. With the growing adoption of multi-agent systems (MAS) in agentic web services such as Grok Bot and WorkBuddy, routing must extend beyond model selection to jointly determine model assignments, collaboration modes, agent counts, interaction rounds, and the skills and subtasks assigned to each agent. For service providers handling Web queries across diverse domains and difficulty levels, adaptively selecting MAS con-figurations to jointly optimize reasoning performance and compute cost has become a central research problem.

Existing MAS routing research primarily improves routing de-cisions through two mechanisms. Parametric policy optimization internalizes execution feedback into router parameters through reinforcement learning or feedback-conditioned distillation, learn-ing policies for model assignment and system orchestration [13, 25, 44, 59]. Explicit experience evolution updates retrievable ex-ecution records, routing rules, or orchestration skills, allowing accumulated experience to guide subsequent decisions without gradient updates to the router [27, 31, 41, 60]. Connecting experi-ence reuse with policy learning is particularly challenging for joint MAS configuration: the benefits of a model, collaboration mode, or resource allocation depend jointly on task requirements and the surrounding configuration choices. Reusable experience must therefore preserve these conditions of applicability, while effective policy learning must translate the relevant knowledge into the ability to plan new configurations. As illustrated in Figure 1, this raises a central open question: How can configuration experience be distilled into reusable knowledge of conditional dependencies and internalized in the router’s pre-execution planning policy to improve the system-level trade-off between accuracy and cost? Addressing this question presents two challenges, as highlighted in Figure 2. (i) Discovering reusable routing principles within a complex, multidimensional configuration space. Jointly select-ing models, collaboration modes, agent counts, interaction rounds, and skills causes a combinatorial explosion in the configuration space, making exhaustive evaluation computationally prohibitive [48]. Moreover, because configuration benefits depend on both the task and the combination of choices, a single execution trajectory reveals only the outcome under a specific configuration [56]. It provides insufficient evidence to identify necessary, redundant, or suboptimal decisions. The router must therefore move beyond learning from isolated outcomes and analyze execution trajectories across tasks and configurations to uncover conditional configura-tion patterns that generalize to subsequent tasks. (ii) Translat-ing post-execution experience into fine-grained supervision for pre-execution routing. Existing reinforcement learning ap-proaches to routing derive reward signals solely from highly sparse feedback on final task success and computational cost [7, 30, 61]. However, a complete MAS configuration involves multiple coupled planning decisions. Terminal rewards provide limited guidance on which decisions are effective, which waste resources, and how individual configuration choices should be adjusted. Even when valuable routing insights can be distilled from historical trajec-tories, they do not automatically translate into effective action selection at specific decision states of the current routing policy. This mismatch between high-dimensional combinatorial decisions and coarse, sparse execution feedback limits the router’s ability to learn efficiently and improve continually from limited execution experience. To address these challenges, we propose EvoRouter , an adaptive multi-agent routing framework built around an insight-guided self-improvement loop. To address the first challenge , we conduct preliminary experiments that systematically examine how config-uration changes affect reasoning performance and computational cost across tasks, revealing task dependence, diminishing marginal returns, and configuration interdependence. We then design an LLM-based expert that distills routing insights by periodically ag-gregating configurations, execution outcomes, and costs across tasks. The expert derives conditional insights into task-specific ca-pability bottlenecks, marginal returns from resource scaling, and interactions among configuration choices. These insights guide exploration according to task characteristics, steering the router toward optimal configurations. To address the second challenge ,we develop a router training method that combines privileged on-policy distillation (OPD) with cost-aware reinforcement learning (RL). OPD transforms configuration insights accumulated across trajectories into dense, token-level rewards informed by routing insights, while RL optimizes the performance–cost trade-off using end-to-end execution outcomes. These complementary training sig-nals address the challenge of learning interdependent multi-agent configuration decisions from sparse execution feedback. Our main contributions are summarized as follows: 

1. Conditional routing insights distillation. We identify task dependence, diminishing marginal returns, and interdependence among MAS configuration choices. We distill cross-trajectory per-formance–cost feedback into configuration insights with explicit applicability conditions to guide exploration.

## 2 Related Work 

LLM Routing and Multi-Agent Orchestration. LLM rout-ing spans per-query model selection [4, 10–12, 36, 47] and output-budget allocation [54], sequential model invocation [39, 61], and joint MAS configuration [25, 44, 53, 59, 63]. Beyond team design, routers adapt delegation [7, 13], agent or context selection [32, 62], and execution state [28, 41]. Experience-based approaches retain reusable routing knowledge [31, 50, 60] or co-evolve routing with worker capabilities [19]. RSI-Router[27] evolves subtask assign-ments and model-specific skills through Pareto selection. EvoRouter targets pre-execution joint configuration over fixed heterogeneous workers, informed by our analysis of task-dependent scaling and configuration interactions. 

Post-Training for LLMs. LLM post-training commonly com-bines supervised fine-tuning (SFT) on demonstrations with prefer-ence optimization [37, 40]. Reinforcement learning with verifiable rewards further develops reasoning capabilities from outcome feed-back [16]. Complementing reward-based optimization, on-policy distillation provides teacher supervision on student-generated se-quences and can reduce the training–inference distribution mis-match associated with offline distillation [2]. Recent methods enrich this supervision with textual feedback [20], trajectory-derived skills [49, 52], and role-specific coordination feedback [64]. Building on these principles, EvoRouter combines group-relative RL with OPD on student-generated configuration plans, conditioning the teacher on evolving cross-task insights and current execution feedback. The resulting policy operates without privileged feedback at inference.

## 4 Method 

We parameterize the routing policy as 𝜋 𝜃 and initialize it through SFT. We then collect online trajectories across diverse task cate-gories and employ an insight distillation expert to iteratively extract routing insights, which are internalized into the policy through training. This establishes an iterative evolution loop, sustained by reinforcement learning and on-policy distillation in an online environment, as illustrated in Fig. 4. 

## 4.1 Evolution Loop 

Routing and execution. We construct the router context 𝑥 ,comprising role specifications, task descriptions and available rout-ing resources. The router first analyzes the task and reasons within the <analysis> tag, then generates a structured plan as defined in Eq. (1) within the <plan> tag. A deterministic executor in the environment parses this plan and instantiates the specified MAS. The MAS then executes the plan in the environment, produc-ing execution outcomes that are returned as observations for the router’s subsequent response. The router analyzes these observa-tions within the <analysis> tag and generates the final answer ˆ 𝑦 

within the <answer> tag, forming a two-stage trajectory 𝜏 . Each trajectory records the task description, multi-agent configuration, execution outcomes, and verifier-evaluated final answer. 

Sampling and evolution. We deploy the router in an online environment and sample execution trajectories from a training set spanning diverse capability dimensions. Building on the observa-tions from our preliminary experiments (Section 3.1), we develop an insight distillation expert to analyze these trajectories and continu-ally refine routing insights. The expert integrates newly observed routing patterns from recent online trajectories with accumulated insights, capturing task-dependent preferences for resources and subtask decomposition strategies across different domains, diffi-culty levels, and budgets. This process enables routing knowledge to evolve continuously as new execution insights accumulate, as detailed in Section 4.4.

This advantage extends to unseen Code and Reasoning domains , where EvoRouter achieves sample-weighted accuracies of 74.67% to 78.93%, surpassing the strongest baseline by 7.74 to 12.00 percentage points. Compute efficiency. The left panel of Figure 5 highlights EvoRouter’s favorable position on the accuracy–cost Pareto frontier. Accounting for router overhead, the right panel shows that total inference cost reaches only 18.94k units, remaining 76.5% and 39.2% below MasRouter and RCR-Router, respectively. This confirms that substantial worker-level compute savings translate into end-to-end efficiency gains despite the additional planning overhead.

## 5.3 Framework Analysis 

Ablation study. Table 3 quantifies the contributions of RL, OPD, and distilled Insights. Compared with SFT alone, full EvoRouter-4B improves in-domain and out-of-domain accuracy by 8.92 and 11.47 percentage points while reducing MAS execution costs by 9.0% and 13.9%, respectively. Under matched training iterations, OPD without Insights yields only 1.31- and 1.06-point accuracy gains over RL, whereas insight-guided OPD boosts these gains to 5.46 and 4.80 points. This substantial gap highlights the importance of distilling cross-trajectory insights into actionable supervision for effective routing. 

Evolution dynamics. Figure 6 illustrates how iterative insight-guided policy refinement progressively improves EvoRouter-LLaMa-8B’s performance. Early updates improve success rate by 2.62 points while reducing compute by 16.4%, reflecting more efficient resource selection; Subsequent updates leverage additional compute for further accuracy gains, before later refinements achieve another 1.35-point improvement with 7.4% lower cost. These dynamics demonstrate how insight-guided evolution progres-sively refines the trade-off between accuracy and computational efficiency. Training loss curves for all three backbones are provided in Appendix A.3.

## 6 Conclusion 

We presented EvoRouter, a framework that learns to jointly con-figure heterogeneous LLM-based MAS from execution experience. Combining cost-aware reinforcement learning with on-policy distil-lation, EvoRouter internalizes cross-task configuration insights and trajectory feedback into its routing policy, enabling deployment without privileged feedback. Across 21 datasets spanning seven domains, EvoRouter achieves higher average accuracy at lower computational cost than the evaluated routing baselines in both in-domain and out-of-domain settings. Our current framework is designed for cloud-based agent services. Future work will extend EvoRouter to resource-constrained edge environments through coordinated cloud–edge routing that accounts for device hetero-geneity and inter-agent communication overhead.

## A Experimental Details A.1 Resource 

All LLMs in the pool use temperature 1.0 and maximum output length 1,024 tokens (4,096 for code tasks). For multimodal tasks, models lacking multimodal support receive a fixed placeholder declaring image invisibility, forcing them to answer solely based on text. In generalization experiments (Section 5.4), the model pool comprises Qwen3.8-Flash, Kimi-K2.8-Preview, and Qwen3.8-Max; the collaboration mode pool comprises Self-Consistency and Hier-archical; and the skill pool contains skills unused elsewhere. Details of the collaboration modes are as follows: 

• IO : A single agent answers in a single turn. 

• CoT : A single agent reasons step-by-step across multiple turns before delivering the final answer. 

• Reflection : A single agent iteratively reflects on its previ-ous response to generate a revised answer. 

• Self-Consistency : A single agent is invoked multiple times independently. A subsequent invocation then inspects all candidate answers, evaluates consistency, resolves discrep-ancies, and aggregates the final result. 

• Chain : Agents are activated sequentially, each receiving its predecessor’s output. When an agent exhausts its allocated reasoning turns, the next agent is triggered. 

• FullConnected : All agents are activated concurrently, re-ceiving peers’ responses from the prior turn. Final-turn responses are routed to the router to synthesize the answer. 

• Debate : All agents run concurrently, critiquing peers or re-butting critiques in subsequent turns. Final-turn responses are routed to the router for answer synthesis. 

• Hierarchical : The initial agent plans task decomposition and scheduling, intermediate agents execute independently in parallel, and the final agent synthesizes findings. Turn limits govern reasoning turns per agent. Certain collaboration modes impose cross-configuration con-straints. For example, if the router pairs CoT with two agents, the MAS plan is rejected (as CoT admits at most one agent) and marked incorrect. 

## A.2 Dataset 

We construct a dataset comprising 12,800 questions across five domains, as described in Section 5.1. The dataset is partitioned into 10,500 training, 1,000 development, and 1,300 test questions. For out-of-domain evaluation, we use 175 questions from the Live-CodeBench [22] and 200 from the BBH-LD [45]. For each training task domain, we set a shared budget in our cost units. We calibrate it from pre-collected successful traces by computing the 25th percentile of trace costs for each question, taking the median across questions in the domain, and adding a 15% margin, with a minimum budget of 512. Budgets vary across domains (as well as trace collections); for example, the budget for the math tasks is 12,374.00, and 5,722.02 for commonsense tasks. 

## A.3 Training 

We evaluate three router backbones: Qwen3-4B, Qwen3-8B, and Llama-3.1-8B, yielding EvoRouter-4B, EvoRouter-8B, and EvoRouter-LLaMa-8B, respectively, through our iterative training framework. All experiments run on 8 NVIDIA A100 80GB GPUs. Task sets across SFT, RL, and evaluation are mutually disjoint. For supervised initialization, DeepSeek-V4-Pro serves as a boot-strap router to collect trajectories, yielding 2,000 filtered instances to fine-tune each backbone for 2 epochs. In subsequent training, we use a batch size of 8 with 16 rollouts per question and a learning rate of 3 × 10 −6, setting 𝛽 = 0.001, 𝑐 max = 0.1, 𝜆 𝐷 = 0.03, and 

𝛼 = 0.25. For on-policy distillation, Qwen3-32B and Llama-3.1-70B serve as teachers for the Qwen and Llama backbones, respectively. DeepSeek-V4-Pro also acts as the insight distillation expert, leverag-ing its context window and reasoning capabilities to analyze dozens of trajectories simultaneously, but does not directly supervise the student.
