# ICLHerd: Herding-Based Data Selection for LLMs with In-Context Learning as a Proxy

Canada CIFAR AI Chair 

Data selection plays a central role in modern large language model training, as the quality of training data strongly influences downstream performance. A common approach is to curate a development set that encodes the desired skills (e.g., reasoning or multilinguality) and select data that are similar to them. Existing methods compute similarity using cosine distance over either the model’s hidden states or gradients. However, we observe that this max-similarity strategy induces a mode-seeking bias: the selected data clusters tightly around the development samples. To address this, we propose ICLHerd, a data selection framework that leverages the von Mises–Fisher kernel to balance mode-seeking with mode-averaging. We further introduce in-context learning as a validation proxy, enabling efficient hyperparameter search over the balance trade-off. Results show that ICLHerd outperforms existing LLM data selection algorithms, highlighting the importance of balancing mode-seeking and mode-averaging.

# 1 Introduction 

Data selection is the task of choosing training samples from a data pool in order to maximize model performance given a budget of training data. This is especially important in the large language model (LLM) era, where the candidate data pool is potentially the entire Internet (Li et al., 2024a; Penedo et al., 2024; Wenzek et al., 2020). In modern LLM training, data selection is usually one of the most crucial steps, and researchers rely heavily on intuition and trial-and-error to curate an appropriate training set tailored for the desired model capability. For example, DeepSeek-V4 incorporated different filtering strategies to remove templated data (e.g., repetitive html scripts) and mitigate the risk of model collapse (Xu et al., 2026); Qwen 3 was trained across a selected set of 119 languages and dialects in an attempt to improve data diversity and improve the model’s multilingual skills (Yang et al., 2025); Llama 4 was trained on what the technical report claimed as “specialized datasets” to improve the model’s long-context capabilities (Meta AI, 2025). It is important to note that the training recipes of these frontier open-weight models are not publicly available. This leaves a gap in systematic research on data selection, as the scale of training data (often trillions of tokens) makes it infeasible to ablate individual selection strategies, limiting the scientific rigor of these technical reports. Existing open research on LLM data selection generally uses a development (dev) set to guide the selection process, where the dev samples encode the desired capabilities, e.g., math and reasoning. A promising direction is to embed all the samples and select training data based on the similarity to the dev set. Xia et al. (2024) propose LESS, which embeds training samples via down-projected LoRA gradients, and at each iteration, selects the training sample that maximizes cosine similarity to any dev sample. Ivison et al. (2025) propose RDS+, which embeds samples using the model’s own hidden states for efficiency, and employs a round-robin selection that cycles through dev samples in fixed order, matching each dev sample in turn to promote data diversity. Despite the efforts, we observe that these algorithms suffer from the mode-seeking problem, where 1arXiv:2610.27142v1 [cs.CL] 19 Oct 2026 Preprint Wen et al. 

the selected dataset is overly crowded around the dev samples. Here, a mode refers to a peak in the embedding space, and both algorithms tend to select samples that are close to one or a few peaks of the dev distribution: LESS greedily pick the sample that match well against any of the dev samples, whereas RDS+ attempt to match all dev samples in a round-robin fashion. Alternatively, we may also select data based on the mean embedding of the dev set, as opposed to the maximum used in LESS and RDS+. This, on the other hand, will lead to the mode-averaging problem, where the embeddings of the selected dataset will center around the centroid of the dev distribution, losing the diversity of capabilities encoded by different dev samples. To this end, we propose ICLHerd, a data selection framework based on the principled data herding scheme (Chen et al., 2010; Welling, 2009), where LESS and RDS+ emerge as special cases. The general idea is to make the distribution of selected samples close to that of the dev set. We use the maximum mean discrepancy (MMD, Gretton et al., 2012) to measure the similarity between two distribution based on the selected samples and those in the dev set. In particular, we adopt the von Mises–Fisher (vMF) kernel (Hall et al., 1987) on normalized features as the similarity measure, which operates on cosine similarities, since LLM representations are commonly compared by their direction rather than their magnitude (Banerjee et al., 2005; Gao et al., 2021; Reimers and Gurevych, 2019). We also design a fused kernel that combines hidden-state and gradient representations, allowing us to leverage their complementary signals for data selection. Overall, the data selection reduces to the problem of looking for similar samples with a diversity penalty. We apply the herding algorithm (Chen et al., 2010; Welling, 2009) for optimization, which greedily selects the best sample at a time and adjusts the diversity penalty accordingly. To efficiently tune the balance between mode averaging and mode seeking, we further propose in-context-learning-as-a-proxy for our ICLHerd framework. Typically, hyperparameter tuning on data selection requires repeatedly training the model and validating the model’s performance, which can be prohibitively expensive. Our proposed ICLHerd circumvents this problem by validating through in-context learning, where we put the selected data as a prompt and evaluate its loss on the dev set. Note that this is especially efficient due to prefix caching, as the same prompt is shared among dev samples. Our results establish a connection between in-context learning and gradient-descent-based learning performance. Overall, we propose a ICLHerd framework of data selection for training LLMs. Our contributions are three-fold: (1) we address the mode-averaging and mode-seeking problems in data selection for LLMs; (2) we design a fused vMF kernel combining hidden states and gradients to control this balance; and (3) we propose in-context-learning-as-a-proxy for efficiently tuning it. 

# 2 Related Work 

Data selection for language model training aims to choose a subset of a large candidate pool to reduce training costs (Albalak et al., 2024; Qin et al., 2025). Existing methods span different paradigms. 

Classifier-based data filtering. Classifier-based methods train a lightweight classifier to separate desired samples from the raw pool, and select samples by a threshold on the classifier score, with early studies in machine learning focusing on identifying mislabeled examples and eliminating noise (Brodley and Friedl, 1999; Wilson, 1972). For LLM training, the classifiers are usually trained with high-quality text as positive data, e.g., Wikipedia (Brown et al., 2020; Gao et al., 2020). Alternatively, positive samples can also be task-specific data, such as instruction following (Li et al., 2024a; Xie et al., 2023). More recently, researchers also use an LLM to annotate positive samples and ensemble several classifiers for different aspects of data quality (Penedo et al., 2024; Su et al., 2025). While these methods are efficient enough for pretraining pools, they score each document independently and do not consider the distribution of the selected set. 

Loss and perplexity scoring. Another family of data selection methods filter examples by a language model’s loss or perplexity, treating this as a proxy for sample utility (Lewis and Gale, 1994; Moore and Lewis, 2010; Wenzek et al., 2020). Existing approaches for LLM training differ on which part of the loss 2Preprint ICLHerd: Herding-Based Data Selection for LLMs with In-Context Learning as a Proxy 

range to preserve: the hardest examples, the middle (Ankner et al., 2024; Marion et al., 2023), or the easiest, such as the most likely response to each instruction (Zhang et al., 2025). For instruction tuning, Li et al. (2024b) compare the loss of the response with and without the instruction, ensuring that difficulty reflects the instruction rather than the response alone. However, a loss score only measures how difficult an example is for the model; since a useful example can be either easy or hard, such methods may overlook other aspects of data quality (Sachdeva et al., 2026; Wettig et al., 2024). 

Similarity-based data filtering. Similarity-based methods select data that are most similar to a small dev set from the target task (Huang et al., 2006; Koh and Liang, 2017; Shimodaira, 2000). Specifically, they embed the pool and dev samples into a representation space and compute similarity between them. The choice of representation varies, including the gradient of the model’s loss (Dai et al., 2025; Xia et al., 2024), the hidden states of the model being trained (Ivison et al., 2025), or the output of a separate embedding model (Ivison et al., 2025; Yin and Rush, 2025). They also differ in their selection scheme: Xia et al. (2024) rank examples by their best match to any dev sample; Ivison et al. (2025) go through the dev samples in a round-robin fashion to equally optimize for every dev sample; and Dai et al. (2025) iteratively select the sample that most benefits the currently most underrepresented task. Despite these efforts, there is a lack of systematic study on which features and which selection scheme to use. These similarity-based methods also rely on the best matches to the dev samples, whereas our ICLHerd selects a set of samples whose distribution is close to that of the dev set. 

LLM-as-a-judge for data filtering. LLM-as-a-judge (LaaJ) uses a strong language model to evaluate text (Gu et al., 2024; Liu et al., 2023; Zheng et al., 2023), and has also been used for data selection by rating each training example and keeping the high-scoring ones (Chen et al., 2024; Sachdeva et al., 2026; Wettig et al., 2024). These methods differ in how they define quality, e.g., accuracy (Chen et al., 2024), complexity (Liu et al., 2024), and multi-criteria rubrics (Wettig et al., 2024). Researchers also develop different ways to elicit a judgment, e.g., a 0–5 rating (Chen et al., 2024), the probability of a “yes” answer (Sachdeva et al., 2026), and pairwise comparison (Wettig et al., 2024). However, scoring a whole pool with a large judge is computationally expensive; to address this, some methods distill judge labels into a small trained scorer (Liu et al., 2024; Wettig et al., 2024). Since each example is scored independently and may be redundant, a separate mechanism for coverage is often added to the approach, such as a diversity filter and a sampling temperature (Liu et al., 2024; Sachdeva et al., 2026; Wettig et al., 2024). Recent work shows that random selection and hidden-state similarity are strong baselines for LLMs (Did-dee and Ippolito, 2025; Ivison et al., 2025), a finding consistent with our results. This suggests that data selection for LLMs is still challenging and warrants further investigation.

# 3.2 Our ICLHerd Approach 

The overall goal of our approach is to select a dataset 𝒟 sel , whose distribution is close to that of 

𝒟 dev . However, we only have discrete data samples in 𝒟 sel and 𝒟 dev , without an explicit form of their distributions. Thus, we use the maximum mean discrepancy (Gretton et al., 2012) to measure distribution similarity based on samples using a kernel function. With such a formulation, the objective becomes selecting samples that are close to 𝒟 dev , but with a diversity penalty. We minimize this objective by the classic herding algorithm, which selects samples greedily while maintaining a running profile of diversity scores. For neural networks, the von Mises–Fisher kernel (Hall et al., 1987) is often preferred (Kobayashi, 2018), as the representations are often compared by their direction rather than the Euclidean distance. # 4.1 Setups 

Selection pool dataset. Following Ivison et al. (2025), we use the unfiltered Tülu 2 SFT mixture dataset (Ivison et al., 2023) as our selection pool 𝒟 , containing approximately 5.8M samples from sources including Open Orca (Mukherjee et al., 2023), FLAN (Chung et al., 2024), and WizardLM Evol-Instruct (Xu et al., 2024). This pool combines data across various skills, requiring the selection algorithm to identify examples relevant to each target task. 

Evaluation tasks and datasets. We evaluate all methods on five tasks in a zero-shot setting: GSM8K (Cobbe et al., 2021), MLQA (Lewis et al., 2020), DROP (Dua et al., 2019), XSum (Narayan et al., 2018), and OASST1 (Köpf et al., 2023). These tasks cover a diverse range of skills, including mathematical reasoning, multilingual question answering, reading comprehension, summarization, and instruction following. For in-depth analyses, we focus on GSM8K and MLQA to test two distinct capabilities: reasoning and multilinguality. Details are presented in Appendix A.

As seen, ICLHerd outperforms both RDS+ and LESS on average and achieves the highest performance in 8 out of 10 settings. We perform a statistical test against RDS+, which is the strongest baseline. Including the 1.7B results, ICLHerd outperforms RDS+ under 13 of the 15 setups, which is statistically significant under a two-sided binomial test ( 𝑝 ≈ 0.007). These results indicate that a small model with ICLHerd can select data that are effective for significantly larger models, suggesting that the cost of data selection can be paid once with a small model and reused for larger ones.

This is consistent with existing literature, which prefers using direction rather than magnitude for high-dimensional embeddings (Banerjee et al., 2005; Gao et al., 2021; Reimers and Gurevych, 2019). Both RBF and vMF kernels offer an exponential decay when samples are moved apart, which enables a balance between mode averaging and mode seeking; they outperform the Euclidean and cosine kernels by a large margin. Furthermore, the angular similarity of the vMF kernel outperforms Euclidean distance, being the most effective kernel across all tested options.

This is because the dev set enters the objective only through the average kernel similarity, which a few samples already estimate well. This highlights the robustness of our approach across different dev set sizes.

In this work, we propose ICLHerd, a data selection framework for LLMs based on data herding, which balances mode averaging and mode seeking with a vMF kernel fused over hidden states and gradients. # Appendix 

# A Implementation Details 

We use Qwen3-1.7B (Yang et al., 2025) and set the training budget to 10K, i.e., selecting 10K samples for training each task. Following Ivison et al. (2025), we fine-tune for 2 epochs with a learning rate of 2e-5, and following Xia et al. (2024), we employ LoRA with rank 128. We set vMF concentration 𝜅 by validation (Section 3). 

# B Dataset Details 

We evaluate our method on the following five tasks: 

• GSM8K (Cobbe et al., 2021): grade-school math word problems, evaluated by exact match of the final answer. 

• MLQA (Lewis et al., 2020): extractive question answering over passages in seven languages, evaluated by F1 averaged across languages. 

• DROP (Dua et al., 2019): reading comprehension requiring discrete reasoning (e.g., counting and arithmetic), also evaluated by F1. 

• XSum (Narayan et al., 2018): one-sentence summarization of BBC articles, evaluated by ROUGE-L. 

• OASST1 (Köpf et al., 2023): open-ended instruction following, evaluated by ROUGE-L relative to the reference response. Table 9 lists the number of dev and test samples for each task. For tasks without a dedicated dev split, we use samples from the training set as the dev set. MLQA provides no training set, so we sample 500 dev and 1,000 test samples per language from its validation and test splits, respectively, to keep both sets balanced across languages. For XSum, we subsample 1,000 dev and 1,000 test samples for efficiency, as summarization requires reading long contexts. For OASST1, we split 500 dev and 500 test samples from the Tülu 2 pool and remove all OASST1 samples from the selection pool to prevent data leakage.
