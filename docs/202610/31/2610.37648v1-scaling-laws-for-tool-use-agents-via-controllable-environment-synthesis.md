## 摘要
我们探索如何构建能够完成复杂多步任务的高性能大语言模型（LLM）工具使用智能体。具体而言，我们研究合成生成的工具使用环境中的数据组成如何影响此类智能体的训练。为此，我们提出 SynthAPI 流水线，它沿工具、任务以及工具所操作数据库这三个维度显式控制生成环境的多样性。通过在 458,752 个任务上系统改变 SynthAPI 的生成控制，并训练四种不同规模的 849 个模型，我们推导出一个缩放定律，可根据合成环境的规模与组成预测下游工具使用智能体的泛化性能。这些可预测的关系揭示了若干关于扩展工具使用智能体数据的经验。随着数据预算增长，扩展工具和数据库多样性比增加任务数量更有效，而提高数据复杂度会带来更大收益。按照这些发现进行扩展，所得智能体在四个评估基准上优于使用先前工作在大型工具使用智能体和合成环境生成中的数据训练的模型。

## Abstract
We explore how to build performant large language model (LLM) tool-use agents that complete complex, multi-step tasks. Specifically, we study how data composition in synthetically generated tool-use environments affects the training of such agents. To do so, we propose the SynthAPI pipeline, which explicitly controls the diversity of generated environments along the axes of tools, tasks, and the databases on which the tools operate. By systematically varying SynthAPI's generation controls in 458,752 tasks across 849 trained models of four different sizes, we derive a scaling law that predicts downstream tool-use agent generalization based on the scale and composition of the synthesized environments. These predictable relationships reveal several lessons for scaling tool-use agent data. As data budgets grow, scaling tool and database diversity becomes more effective than increasing the number of tasks, and increasing data complexity yields larger gains. Scaling according to these findings yields agents that outperform models trained on data from prior work in large-scale tool-use agent and synthetic environment generation across four evaluation benchmarks.

## 2. 方法论

### 2.1 核心思想

- 提出 **SynthAPI**：一个可控的多步工具使用环境合成流水线，分两阶段：
  1. **App 生成**：由 builder LLM（Gemini-3.1 Pro，禁用联网）从零生成 Python 实现的“应用”，包含元数据、数据库 schema 与 API 层；
  2. **任务生成**：基于 App 功能生成带初始数据库状态、可执行验证器与 oracle 解的任务。
- 关键区别：相比先前工作，SynthAPI 对**工具（A）、任务（T）、数据库广度（S）、数据库深度/复杂度（D）**提供显式生成控制，从而可系统研究固定预算下的数据分配。

### 2.2 关键技术细节

- **App 生成流程**：
  - 生成 app 元数据：名称、描述、8 类 taxonomy（购物、音乐、生产力、金融、健身、消息、工具、社交）、功能列表；
  - 生成 `db.py`：Enum 与 dataclass 定义数据模式；
  - 生成 `apis.py`：Python 函数，接收数据库对象与输入参数，读写数据对象；公开函数即 agent 可调用工具；
  - API 仅能通过四种 CRUD 函数访问数据库，便于记录状态变更日志。
- **任务定义**：任务为四元组 \(T=(x, v, Db_0, \pi^*)\)：
  - \(x\)：无歧义、无需外部交互的任务指令；
  - \(v\)：Python 验证器，输入起始/当前数据库状态与可选答案，输出二值成功指示；
  - \(Db_0\)：初始数据库状态，先构造最小可行核心状态，再叠加 \(D-1\) 批干扰数据，共 \(D\) 批；
  - \(\pi^*\)：oracle 求解程序，仅调用公开 API 完成任务，用于可行性过滤；
  - 过滤条件：拒绝不满足 \(v(Db_0)=0\) 且 \(v(\text{Exec}(\pi^*, Db_0))=1\) 的任务。
- **环境接口**：
  - 采用 Gymnasium 格式，agent 每轮输出单个 Python 代码块，可一次调用多个工具并使用循环/条件；
  - 工具结果以 JSON 返回，dataclass 逐字段序列化；
  - 提供元工具 `list_apps`、`list_tools`、`get_tool_documentation`、`complete_task`，实现基于发现的工具加载，降低上下文长度并支持跨工具集迁移；
  - 每 episode 上限 32 步，观测截断至 2048 tokens。
- **控制变量定义**：
  - \(A\)：App 数量（工具多样性）；
  - \(T\)：每 App 任务数；
  - \(S\)：每任务指令对应的初始数据库实例数（数据库广度）；
  - \(D\)：每个初始数据库的干扰数据批次数（数据库复杂度/深度）；
  - 总任务数 \(N = A \cdot T \cdot S\)，\(D\) 不改变任务数。
- **分析模型**：
  - 先对固定 \(A\) 拟合广义 logistic 曲线：\(\hat P_{M,A}(N)=U\cdot\sigma(b+b_N\log_2 N)^\nu\)；
  - 再提出数据组成依赖的缩放律：
    \[
    \hat P^{1}_{M}(A,T,S,D)=\sigma(c_0+c_A\log_2(A\cdot S\cdot D))\;\sigma(b_0+b_T\log_2 T)^\nu
    \]
  - 对照基线为仅依赖任务数的缩放律 \(\hat P^{0}_{M}(N)=U\sigma(b_0+b_N\log_2 N)^\nu\)；
  - 用 Chinchilla 近似 \(C\approx 6ML\) 计算训练 FLOPs，留出 FLOPs 最高的 25% 运行做外推验证（最大 16× 外推）。
- **训练流程**：用 GLM-5.2 作为专家，每任务最多尝试 4 次，保留首次成功轨迹；对 Qwen3.5 学生模型做 SFT 蒸馏，loss 仅作用于推理与动作 token。

## 3. 实验设计

- **合成数据规模**：
  - 64 个 App，10,472 个 API（6,266 写 / 4,206 读），每 App API 中位数 144（范围 51–443）；
  - 每 App 数据类中位数 55（10–135），功能数中位数 81（31–143）；
  - 共 458,752 个任务；每任务中位使用 2 个功能（1–7）；核心数据库状态中位 59 行；
  - SFT 数据共 5.9B tokens，其中 721M 为推理与动作监督 token。
- **模型与训练**：Qwen3.5 家族 2B/4B/9B/27B，共训练 **849 个模型**；默认 1 epoch，按验证损失早停并选最优 checkpoint。
- **Benchmark**：
  - **AppWorld**：Test-Normal（168 任务）与 Test-Challenge（417 任务），9 个 App、457 个 API；
  - **BFCLv3 Multi-Turn**：129 个 API、8 个领域、800 个多轮任务；
  - **ASTRA-Bench**：6 个 App、27 个 API、939 个 High 难度任务，persona 驱动；
  - **SynthAPI-Holdout**：新生成 4 个 App × 25 任务，测分布内跨 App 泛化。
- **诊断集**：AppWorld + SynthAPI-Holdout（因全量评测需约 180 万 episode），使用归一化分数 \(P(\theta)\in[0,1]\) 做缩放分析。
- **对比方法**：
  - **数据配方消融**：SynthAPI-SubOpt（\(A=32,T=1024,S=1,D=2\)）vs. SynthAPI-Opt（\(A=64,T=128,S=4,D=4\)，同任务预算）vs. SynthAPI-Big（全量数据训练 4 epoch）；
  - **大规模先前数据**：Nemotron-Agentic（335k 轨迹，LLM 模拟工具响应）；
  - **AppWorld 基线**：ToolACE、ToolAlpaca、SimSAT；
  - **BFCL 基线**：Agent World Model、EnvScaler、EnvFactory；
  - **Zero-shot** 起点。
- **外部验证**：在另一合成流水线 SimSAT 上重复 App 数与任务数分配实验（\(A\in\{8,16,32\}\)，\(N\in\{128,256,512,1024\}\)）。
